### ทำไม 30B-A3B ไม่ใช่ 8B หรือ 32B

Qwen3-VL มี 2B / 4B / 8B / 32B (dense) และ 30B-A3B / 235B-A22B (MoE)

- **30B-A3B** ← มะขามเลือกเอง 2026-07-28 MoE เหมือนกัน active 3B เท่ากัน total ใกล้กัน = คุมตัวแปรครบที่สุด
- 32B dense — เลขรวมใกล้ 35B กว่า (32 vs 35) แต่ active param ต่างกัน **10 เท่า** ถ้าชนะจะแยกไม่ออกว่า
  ชนะเพราะ Qwen3-VL ดีกว่า หรือชนะเพราะใช้ compute ต่อ token มากกว่า 10 เท่า
- 8B dense — ถูกกว่ามากและรันบนโน้ตบุ๊กได้เต็มก้อน แต่คนละสเกล เก็บไว้รอบถัดไป
  (preset ยังอยู่ในสคริปต์ `MODEL_SIZE=8B` ใช้ได้ทันที)

> **รู้ไว้ล่วงหน้า:** ไฟล์ Q4 ของ 30B-A3B = **18.56 GB** ยังใหญ่กว่า VRAM 8GB ของโน้ตบุ๊ก
> → ต้องแบ่ง CPU/GPU เหมือน t01 ได้ความเร็วระดับเดียวกัน (~3-4 t/s)
> **t02 ไม่ได้แก้ปัญหาความเร็ว** มันตอบคำถามเรื่องความแม่นยำอย่างเดียว

#### บั๊ก 9 🔴 `ip.max_pixels = ...` crash จริงบนเครื่องเช่า — พังตอน Phase 4 บนเครื่องจริง (2026-07-28)

**เจอตอนรันจริง ไม่ใช่ตอน re-check** — Phase 4 (baseline) crash ทันทีตั้งแต่ครั้งแรก:

```
AttributeError: property of 'Qwen2VLImageProcessor' object has no setter
  ip.max_pixels = P["max_pixels"]
```

โค้ดเดิม (ทั้งใน `train_qwen3vl.py` และ `eval_fields.py`) ตั้งค่าความละเอียดภาพ 2 ทางพร้อมกัน —
`ip.max_pixels = ...` / `ip.min_pixels = ...` **และ** `ip.size["longest_edge"] = ...` /
`ip.size["shortest_edge"] = ...` — เขียนไว้แบบ "กันเหนียว" ตอนยังไม่เคยรันจริงบนเครื่องเช่า

ตรวจสดบนเครื่อง (`transformers 5.5.0` ที่ pip ดึงมาจริง ไม่ใช่เวอร์ชันที่เขียนโค้ดตอนนั้น):

```python
>>> hasattr(ip, "max_pixels")
False   # ไม่ใช่แค่ readonly — attribute ไม่มีอยู่เลย
>>> ip.size["longest_edge"] = 5242880   # ← ทางนี้ทำงานได้ปกติ
OK
```

อ่าน source จริงของ `Qwen2VLImageProcessor.preprocess()` (คลาสเดียวกับที่ Qwen3-VL ใช้เป็น
image processor) ยืนยันว่า:
```python
min_pixels = images_kwargs["min_pixels"] if "min_pixels" in images_kwargs else self.size["shortest_edge"]
max_pixels = images_kwargs["max_pixels"] if "max_pixels" in images_kwargs else self.size["longest_edge"]
```
**`self.size[...]` คือกลไกจริงที่มีผลเสมอ** ส่วน `ip.max_pixels`/`ip.min_pixels` เป็น attribute
ที่มีอยู่ใน `__init__` ตอนรับเป็น kwargs (แปลงเข้า `size` ทันที) แต่ไม่มี attribute แยกเก็บไว้
หลังจากนั้นเลย — โค้ดฝั่ง "กันเหนียว" ตายเปล่าตั้งแต่แรก ไม่ได้ตั้งอะไรเพิ่มจริง

แก้: **ลบ `ip.max_pixels = ...` / `ip.min_pixels = ...` ทิ้งทั้งสองไฟล์** เหลือแค่ `ip.size[...]`
ซึ่งพิสูจน์แล้วว่าใช้ได้จริง — และแก้ print statement ที่อ่าน `ip.max_pixels` (จะ crash เหมือนกัน
เพราะ attribute ไม่มีอยู่) ให้อ่านจาก `ip.size['longest_edge']` แทน

**สอนอะไร:** §0.4 เดิมพบบั๊ก 5-8 ข้อจากการ**อ่าน source โค้ด** ก่อนรันจริง แต่บั๊กนี้ผ่านตาไปได้
เพราะดูเผินๆ เหมือน "ตั้งสองทางกันพลาด" ซึ่งฟังดูปลอดภัยกว่า — ที่จริงคือทางหนึ่งพังเงียบ (ไม่มี
attribute จริง Python จะไม่ error จนกว่าจะ *เขียน* ใส่ attribute ที่ไม่รู้จัก ซึ่งก็คือบรรทัดที่ crash)
บทเรียน: โค้ดที่ "ตั้งสองทาง" ไม่ได้แปลว่าปลอดภัยกว่าทางเดียว ถ้าไม่รู้ว่าทางไหนคือทางจริง
