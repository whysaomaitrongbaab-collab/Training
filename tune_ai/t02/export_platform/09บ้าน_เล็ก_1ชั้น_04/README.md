# ผล Qwen t02 บ้าน 09 — ไฟล์สำหรับนำเข้า Constistant

7 ไฟล์ในโฟลเดอร์นี้พร้อมนำเข้าแพลตฟอร์มแล้ว

## วิธีใช้

Constistant → **Drawing Intelligence** → ปุ่ม **"นำเข้าไฟล์สกัดข้อมูล (JSON)"** →
เลือกไฟล์ `.json` **ทั้ง 7 ไฟล์พร้อมกัน** (ไม่ใช่ทีละไฟล์ — adapter ต้องเห็น grid master
พร้อมกับหน้า plan ถึงจะคำนวณระยะได้) → จะขึ้นรายการให้ติ๊กรับ/ไม่รับทีละ element

## ไฟล์มาจากไหน — อ่านก่อนใช้

| ไฟล์ | ที่มา |
|---|---|
| `บ้าน_เล็ก_1ชั้น_04_หน้า00_gridline.json` | **คนทำ ไม่ใช่ผลโมเดล** — รอบนี้ไม่ได้รันหน้า gridline ผ่าน Qwen ถ้าไม่มีไฟล์นี้ ระยะคานทุกเส้นจะเป็น unresolved |
| อีก 6 ไฟล์ (`หน้า06/24/25/26/27/28`) | **ผลดิบจาก Qwen t02** (`Sicilian44/qwen3vl-30b-thai-rc`) ยังไม่ผ่านคนตรวจ |

ทุกไฟล์มีฟิลด์ `_provenance` บอกที่มาไว้ในตัวเอง — `human_reviewed: false` แปลว่า **ห้ามเอาไปใช้เป็น ground truth**

## สร้างใหม่ยังไง

```
python tools/export_qwen_to_platform.py "tune_ai/t02/ผล/09บ้าน_เล็ก_1ชั้น_04" \
    --grid-master "json_แก้ไขแล้ว/09บ้าน_เล็ก_1ชั้น_04/บ้าน_เล็ก_1ชั้น_04_หน้า00_gridline.json" \
    --fix-roof-pattern
```

ตัวแปลงทำแค่ 2 อย่าง: แบน `views[]` ออกมาเป็นไฟล์ละ view (adapter อ่าน `pattern`/`elements`
ที่ระดับไฟล์ แต่โมเดลใส่ไว้ในviews) และเติม wrapper field ที่สเปก §2 บังคับให้ครบ
**เนื้อ element คัดลอกดิบทุกตัวอักษร ไม่มีการแก้ให้สวย**

`--fix-roof-pattern` เปลี่ยน `roof_plan` ของหน้าโครงหลังคาเชิงโครงสร้างเป็น `plan`
(โมเดลติดป้ายผิด — แพลตฟอร์มอ่านเฉพาะ `plan` ถ้าไม่เปลี่ยน คานหลังคาจะหายทั้งหน้า)
ทุกครั้งที่เปลี่ยนจะบันทึกไว้ใน `warnings[]` ของไฟล์นั้น

## ผลจริงตอนนำเข้า (รันผ่าน adapter จริงแล้ว ไม่ใช่คาดเดา)

```
ไฟล์ 7 | grid 9x8 | elements 21 | specs 0 | span คำนวณได้ 0/21
```

ได้ของโครงสร้างจริงมา: `C1` ×8, `C2` ×12, `B2` ×18, ฐานราก, โครงหลังคาเหล็ก
แต่ **ระยะคานคำนวณไม่ได้เลยสักเส้น** เพราะโมเดลไม่ได้ออก `grid_ref_start`/`grid_ref_end`
มาให้ — มันยัดทั้งหน้าไว้ในสตริงเดียวแทน (`"F-F x 1'-2', F-F x 2'-3', ..."`)

เทียบกับ ground truth บ้านเดียวกันผ่าน adapter ตัวเดียวกัน:

| | ไฟล์ | elements | specs | span ได้ |
|---|---|---|---|---|
| Qwen t02 | 7 | 21 | 0 | **0** |
| Ground truth | 104 | 87 | 55 | **18** |

**นี่คือช่องว่างที่ต้องปิดด้วยการทูน ไม่ใช่ด้วยโค้ด** — ตรงกับที่วัดไว้คืน 21/8
(recall 11% บนหน้าแปลนคาน เพราะ t02 เห็นตัวอย่างแค่ ~13 ใบ) ดู `tune_ai/t03/dataset_sizing.md`

## ข้อจำกัดที่เหลือ ระบุตรงๆ

- `specs: 0` — ไม่ได้รันหน้า `section`/`schedule` ของบ้านนี้ผ่าน Qwen เลย จึงไม่มีสเปกเหล็ก
  มาจับคู่กับ element ทำให้ BOQ คิดปริมาณเหล็กไม่ได้
- โมเดลส่ง element ที่ใช้ไม่ได้มา 11 ตัว (ไม่ใช่ object หรือไม่มี `element_id`) — ตัวแปลงทิ้งและรายงานไว้ ไม่ได้ซ่อม
- เห็นข้อบกพร่องของโมเดลติดมาในข้อมูลด้วย เช่น `footинг` (อักษรรัสเซียปน) และ `F4,C1`
  (เอา 2 มาร์คมาต่อกันด้วยจุลภาค) — ปล่อยไว้ตามจริง ไม่แก้ให้
