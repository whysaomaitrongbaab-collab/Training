## ⚠️ อย่า annotate ทุก pattern เท่ากัน — จุดที่ประหยัดได้จริง

**material_list กิน 435 ไฟล์ = 37% ของงาน annotate ทั้งหมด แต่ให้ elements = 0**
ล้นเกินความจำเป็นไปไกลแล้ว — หลังใหม่หยุด annotate ตัวนี้ได้เลย

หลังใหม่ annotate **เฉพาะ pattern ที่ Constistant ใช้จริง** (`raw-extraction-adapter.js`: plan/section/schedule/notes/gridline/material_list) โดยตัด material_list ออก:

```
plan_beam 3.2 + section 20.3 + schedule 6.0 + notes 5.0 + plan_footing 1.8 + gridline 1.1
= ~38 หน้า/หลัง   (แทนที่จะ annotate เต็ม ~107 หน้า/หลัง)
```

**+20 หลัง = annotate ~750 หน้า (ไม่ใช่ 2,140) → plan_beam 35 → ~99**
ประหยัดแรงคน ~65% โดยได้ตัวเลขที่ขยับ recall จริง

## ⚠️ ปัญหาที่ต้องตัดสินใจก่อนวาง t03

**`plan_column` มีแค่ 2 ไฟล์ใน 11 หลัง** — เสาแทบไม่มีหน้าแปลนของตัวเอง มันโผล่เป็น marker ในแปลนคาน/ฐานราก กับเป็นตารางเสา (`column_table_details`) แทน

ถ้า t03 ตั้ง `plan_column` เป็น subtask แยกตาม `pass_design.csv` **มันจะไม่มีข้อมูลเทรนเลย** (2 ตัวอย่าง = เทรนไม่ได้) — ต้องเลือก: รวมกับ `plan_beam`, หรือย้ายไปฝั่ง `schedule`
