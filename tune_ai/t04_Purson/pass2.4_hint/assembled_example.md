## พาร์ทที่ 3 - hint ข้อความ (เฉพาะแขน 2.4a, โค้ดแปะต่อท้ายเอง)

ข้อความข้างล่างนี้คือ **ไฟล์จริง** `image/บ้าน_ใหญ่_1ชั้น_04/บ้าน_ใหญ่_1ชั้น_04_หน้า12_hint.txt`
ที่ `cv_scan.py::cv_hint_text()` สร้างไว้ (ก็อปมาทั้งดุ้น ไม่ตัดต่อ):

```
สิ่งที่เครื่องตรวจภาพ (CV) เห็นบนแผ่นนี้ hint ไม่ใช่คำตอบ
บนภาพมีกรอบหมายเลขกำกับตรงจุดที่เครื่องเห็น เรียงบน→ล่าง ซ้าย→ขวา ดังนี้
- ฐานราก (footing) จำนวน 2 จุด หมายเลข 1 ถึง 2 แถวละ [1, 1]
- คานแนวนอน (beam_h) จำนวน 12 จุด หมายเลข 3 ถึง 14
- คานแนวตั้ง (beam_v) จำนวน 14 จุด หมายเลข 15 ถึง 28
กฎการใช้ hint (สำคัญกว่าความครบ) มีดังนี้
1) hint คือสิ่งที่เครื่องเห็น ไม่ใช่คำตอบ จุดไหนอ่านป้ายบนแบบไม่ออก ใช้ชื่อบรรยาย + ติดธงใน confidence_flags ห้ามแต่งชื่อมาร์คขึ้นเอง
2) hint ไม่ใช่เพดาน เห็น element มากกว่าที่ hint บอก ให้ตอบตามที่เห็น
3) hint ไม่ใช่พื้น อ่านได้จริงน้อยกว่าที่ hint ชี้ ให้ตอบเท่าที่อ่านได้ แล้วบอกใน warnings[] ห้ามเติมให้ครบ
4) จุดที่มีกรอบแต่ไม่มีของจริง ให้บอกใน warnings[] (เครื่องตรวจภาพจับผิดได้)
ทุก element ที่ตรงกับกรอบหมายเลขไหน ให้ใส่ฟิลด์ cv_mark เป็นค่าเท่ากับเลขนั้นด้วย เช่นตรงกับกรอบหมายเลข 7 ให้ใส่ cv_mark เท่ากับ 7 (จับคู่ไม่ได้ก็ไม่ต้องใส่)
```

สังเกต 3 อย่างที่ทำให้บล็อกนี้ปลอดภัย:
- **ไม่มีระยะ/ความยาวสักตัว** - CV วัดได้แต่ห้ามส่ง (จะกลายเป็นสอนโมเดลแหกกฎ "ห้ามเดาระยะจากรูป")
- บอกเป็น **ช่วงเลข** (`#3–#14`) ไม่ไล่รายตัว - pass 2 ต้องการแค่ระดับ "เห็นกี่จุด"
- กฎ 4 ข้อทำให้ hint **ไม่ใช่เพดาน ไม่ใช่พื้น** - โมเดลตอบน้อยกว่า/มากกว่าที่ hint บอกได้เสมอ
  ถ้าซื่อสัตย์ (นี่คือสิ่งที่การทดลองอยากวัด ไม่ใช่บังคับให้ตอบครบ 28)

## ผลลัพธ์ที่เพิ่มจากเดิม: ฟิลด์ `cv_mark`

element ไหนที่โมเดลจับคู่กับกรอบเลขได้ จะมี `"cv_mark": 7` เพิ่มเข้ามาในคำตอบ -
pass 2.4 ยังไม่ใช้ค่านี้ทำอะไร (ใส่เพื่อวัดว่าโมเดลรับคำสั่งรูปแบบนี้เป็นหรือเปล่า)
ตัวที่ใช้จริงคือ pass 3: `tools/merge_guard.py` ใช้ `cv_mark` เช็คว่าโมเดลทำ element ของ CV
หายไปตัวไหน แล้วใส่กลับเป็น stub

## สิ่งที่โค้ดรับประกันให้ (ไม่ต้องกลัวพัง)

`apply_arm()` (ยืนยันด้วยการรันจริง 2026-08-28):
- แขน `2` → content เดิมเป๊ะ ไม่แตะอะไร
- sidecar หาไม่เจอ (บ้าน/หน้าที่ยังไม่ผ่าน pass 1.5) → **กลายเป็นแขน 2 โดยพฤตินัย** พร้อมบันทึก
  `hint_used=false` ลง results - ไม่ error ไม่เดา ไม่สร้าง hint เปล่า
- งานหลายภาพ (เช่น gridline) → สลับเฉพาะใบที่มีภาพมาร์ค ใบอื่นภาพเปล่าตามเดิม

## จะรู้ได้ไงว่าแขนไหนชนะ (ตัดสินด้วยเลข ไม่ใช่ความรู้สึก)

ยิง **หน้าเดียวกัน บ้านเดียวกัน โมเดลเดียวกัน** ทั้ง 3 แขน แล้วเทียบจาก `score_ids()`:

| ตัวชี้วัด | อ่านว่า |
|---|---|
| `recall_printed` (ตัวหลัก) | อ่านมาร์คที่พิมพ์จริงเจอกี่ % |
| จำนวน element ที่ตอบ | เทียบกับ GT - มากไป = หลอน น้อยไป = ตกหล่น |
| จำนวนหลอน (id ไม่มีใน GT) | **ตัวตัดสิน**: ถ้า 2.4 recall ขึ้นแต่หลอนขึ้นด้วย = hint เป็นเชิญหลอน |
| จำนวน `null` ที่ซื่อสัตย์ | ไม่ใช่จุดอ่อน - คือหลักฐานว่าโมเดลทำตามกฎ 3 |

ถ้า 2.4a ชนะ → hint ข้อความช่วยจริง เดินหน้าใช้กับ pass 3 (แขน 2.4b ภาพมาร์ค ยกเลิกแล้ว ไม่ต้องเทียบ)
ถ้าแขน 2 ชนะ → hint รบกวนโมเดลที่ fine-tune แล้ว เลิกแนวนี้ได้โดยไม่เสียดาย (จ่ายแค่ค่ายิง)
