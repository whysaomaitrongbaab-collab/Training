## สัญญาของ hint block (สิ่งที่ต้องมี ไม่ว่าโค้ดจะแก้ถ้อยคำยังไง)

ต่อท้าย prompt ของ pass 2 subtask นั้นๆ (หลังจาก `_common.md` + ตัว prompt subtask):

```
สิ่งที่เครื่องตรวจภาพ (CV) เห็นบนแผ่นนี้ - hint ไม่ใช่คำตอบ
บนภาพมีกรอบหมายเลขกำกับตรงจุดที่เครื่องเห็น เรียงบน→ล่าง ซ้าย→ขวา ดังนี้
- เสา (column) จำนวน 14 จุด หมายเลข 1 ถึง 14 แถวละ [4, 4, 4, 2]
- ฐานราก (footing) จำนวน 14 จุด หมายเลข 15 ถึง 28 แถวละ [4, 4, 4, 2]
กฎการใช้ hint (สำคัญกว่าความครบ) มีดังนี้
1) hint คือสิ่งที่เครื่องเห็น ไม่ใช่คำตอบ - ...
2) hint ไม่ใช่เพดาน - ...
3) hint ไม่ใช่พื้น - ...
4) จุดที่มีกรอบแต่ไม่มีของจริง → บอกใน warnings[] ...
ทุก element ที่ตรงกับกรอบหมายเลขไหน ให้ใส่ฟิลด์ cv_mark เป็นค่าเท่ากับเลขนั้นด้วย
```

**2026-08-29 - บล็อกนี้ปรับให้ไม่มี `.` `_` `*` `#` `:` `;` `\` `|` แล้ว (นอกช่วง field name จริง
เช่น `cv_mark`/`warnings[]`) ตามคำสั่งมะขาม กันโมเดลหลอนจาก markdown noise ในprompt เอง - โค้ดจริง
`cv_hint_text()`/`HINT_RULES_TH` ใน `tools/cv_scan.py` แก้แล้วตรงกับตัวอย่างข้างบนนี้ทุกตัวอักษร**

**ต้องมี 3 อย่างเสมอ:**
1. **แถวสรุปต่อชนิด** เป็นช่วงเลข (`#1–#14`) ไม่ใช่รายตัว - pass 2 ตอบระดับ "เห็นกี่จุด" พอ
   (ต่างจาก pass 3 ที่ต้องรู้ทุก `#n` แยกตัว เพราะต้อง merge กลับ - ดู `../pass3_takeoff/`)
2. **กฎกันหลอน 4 ข้อ** ครบ - ไม่งั้น hint กลายเป็นเพดาน/พื้นที่บังคับให้โมเดลมั่วให้ครบจำนวน
3. **คำสั่ง `cv_mark`** - ให้โมเดล echo เลขกำกับกลับมา แม้ pass 2 เองยังไม่ใช้ค่านี้ (pass 3
   ถึงใช้จริง) แต่ใส่ตั้งแต่ 2.4 เพื่อวัดว่าโมเดลรับคำสั่งรูปแบบนี้ได้หรือเปล่าตั้งแต่ต้น

**ต้องไม่มีเด็ดขาด: ตัวเลขระยะ/ความยาว** CV วัดความยาวคานจากพิกเซลได้ก็จริง แต่ห้ามส่งเข้า
prompt - ขัดกฎเหล็ก `_common.md` ข้อ "ห้ามเดาระยะจากรูปร่างที่เห็น" ส่งเข้าไปคือสอนโมเดลให้แหก
กฎนั้นด้วยมือเราเอง ระยะที่ CV วัดได้ใช้เป็นตัวจับผิดฝั่งโค้ดใน pass 2.5/3 แทน (เทียบแล้วต่าง
กันมาก → ยกธง ไม่ใช่แก้เลขให้)
