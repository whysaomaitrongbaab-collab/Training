# Pass 2.4 — Qwen อ่านแบบจริง + hint จาก CV (แขนทดลอง)

**สถานะ: เขียนโค้ดครบ ยังไม่เคยยิงจริง รอ GPU** — นี่ไม่ใช่ prompt ใหม่ทั้งชุด แต่คือ
**ส่วนต่อท้าย** ของ prompt pass 2 เดิม (`gridline`/`plan`/`section`/`schedule`/`notes`) —
ไฟล์นี้เป็น spec ของส่วนต่อท้ายนั้น **ตัวโค้ดจริงที่สร้างข้อความ (คำต่อคำ) คือ
[`tools/cv_scan.py`](../../../tools/cv_scan.py) `cv_hint_text()`/`HINT_RULES_TH` — ไฟล์นี้
เป็นสัญญา (contract) ว่าเนื้อหาต้องมีอะไรบ้าง ไม่ใช่ก็อปคำต่อคำจากโค้ดมาไว้ที่นี่ กันสองที่
ดริฟท์กัน (แก้กฎ ให้แก้ที่โค้ด แล้วอัปเดตสัญญาที่นี่ถ้าโครงเปลี่ยน)**

## การทดลอง 3 แขน

| แขน | ภาพที่ส่ง | hint ต่อท้าย prompt |
|---|---|---|
| **2** | เปล่า (ของเดิม) | ไม่มี ← ตัวคุม |
| **2.4a** | เปล่า | มี (ข้อความล้วน) |
| **2.4b** | **ภาพมาร์คเลข** (Set-of-Mark, arXiv 2310.11441) | มี |

รันผ่าน `tune_ai/t03/data_before_tune/infer_house_t03.py --arm 2|2.4a|2.4b --cv-dir <sidecar>`
(`apply_arm()` ในไฟล์นั้นเป็นคนสลับภาพ+แปะ hint จริง)

ต้องมี 3 แขนไม่ใช่ 2 — ถ้าเทียบแค่ 2 vs 2.4b แล้วดีขึ้น จะไม่รู้เลยว่าดีเพราะมาร์คบนภาพหรือ
เพราะข้อความ และสองอย่างต้นทุนตอนเอาไปเทรนต่างกันมาก

## สัญญาของ hint block (สิ่งที่ต้องมี ไม่ว่าโค้ดจะแก้ถ้อยคำยังไง)

ต่อท้าย prompt ของ pass 2 subtask นั้นๆ (หลังจาก `_common.md` + ตัว prompt subtask):

```
### สิ่งที่เครื่องตรวจภาพ (CV) เห็นบนแผ่นนี้ — hint ไม่ใช่คำตอบ
บนภาพมีกรอบเลขกำกับ #n ตรงจุดที่เครื่องเห็น เรียงบน→ล่าง ซ้าย→ขวา:
- เสา (column) 14 จุด: #1–#14 แถวละ [4, 4, 4, 2]
- ฐานราก (footing) 14 จุด: #15–#28 แถวละ [4, 4, 4, 2]
กฎการใช้ hint (สำคัญกว่าความครบ):
1. hint คือสิ่งที่เครื่องเห็น ไม่ใช่คำตอบ — ...
2. hint ไม่ใช่เพดาน — ...
3. hint ไม่ใช่พื้น — ...
4. จุดที่มีกรอบแต่ไม่มีของจริง → บอกใน warnings[] ...
ทุก element ที่ตรงกับกรอบเลขไหน ให้ใส่ฟิลด์ "cv_mark": <เลข n> ด้วย
```

**ต้องมี 3 อย่างเสมอ:**
1. **แถวสรุปต่อชนิด** เป็นช่วงเลข (`#1–#14`) ไม่ใช่รายตัว — pass 2 ตอบระดับ "เห็นกี่จุด" พอ
   (ต่างจาก pass 3 ที่ต้องรู้ทุก `#n` แยกตัว เพราะต้อง merge กลับ — ดู `../pass3_takeoff/`)
2. **กฎกันหลอน 4 ข้อ** ครบ — ไม่งั้น hint กลายเป็นเพดาน/พื้นที่บังคับให้โมเดลมั่วให้ครบจำนวน
3. **คำสั่ง `cv_mark`** — ให้โมเดล echo เลขกำกับกลับมา แม้ pass 2 เองยังไม่ใช้ค่านี้ (pass 3
   ถึงใช้จริง) แต่ใส่ตั้งแต่ 2.4 เพื่อวัดว่าโมเดลรับคำสั่งรูปแบบนี้ได้หรือเปล่าตั้งแต่ต้น

**ต้องไม่มีเด็ดขาด: ตัวเลขระยะ/ความยาว** CV วัดความยาวคานจากพิกเซลได้ก็จริง แต่ห้ามส่งเข้า
prompt — ขัดกฎเหล็ก `_common.md` ข้อ "ห้ามเดาระยะจากรูปร่างที่เห็น" ส่งเข้าไปคือสอนโมเดลให้แหก
กฎนั้นด้วยมือเราเอง ระยะที่ CV วัดได้ใช้เป็นตัวจับผิดฝั่งโค้ดใน pass 2.5/3 แทน (เทียบแล้วต่าง
กันมาก → ยกธง ไม่ใช่แก้เลขให้)

## แขน 2.4b: ภาพมาร์คเลขแทนภาพเปล่า

`apply_arm()` สลับ `content[i]["image"]` เป็น path ของ `<stem>_marked.png` (จาก
[pass 1.5](../pass1.5_cv/)) เฉพาะรูปที่มี sidecar — งานหลายภาพ (เช่น gridline ที่ยังไม่ผ่าน
pass 1.5 เพราะไม่ใช่ 1 ใน 4 subtask ผังโครงสร้าง) ใช้ภาพเปล่าเหมือนเดิม ไม่ error

## grid ref ใน hint — ยังไม่ทำ (บันทึกไว้กันคิดว่าลืม)

แผนแรกจะใส่ grid ref ที่ใกล้สุดของแต่ละจุด (`g≈C-1`) แต่ grid master จริงเก็บ `pos_m` (เมตร)
ไม่มีพิกัด pixel — ต้อง detect เส้นกริดในภาพก่อนถึงจะจับคู่ได้ ยังไม่ทำ (ดู
`tune_ai/t03/pass_design_v2.md` หัวข้อ grid ref) hint ปัจจุบันจึงใช้ "แถวเชิงลำดับ" แทน
