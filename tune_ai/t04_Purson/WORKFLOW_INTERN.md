## ⛔ กฎเหล็กก่อนแตะอะไร (อ่าน 1 นาที ประหยัดหายนะ 1 คืน)

1. **ห้ามแก้/ลบไฟล์ใต้ `rawjson_ยังไม่ได้แก้ไขโดนคน/` เด็ดขาด** — ground truth
   ต้องมีคำสั่งมะขามเท่านั้น (กติกาเต็ม: `No_touch_box/docs/rule_of_tune.md`)
2. งานเช่า GPU: **การ์ดถูกก่อนเสมอ** ทดสอบจบ 1 หน้าก่อนขยับการ์ดแรง ·
   **venv แยกเสมอ** ห้าม pip install ลง env ที่มีงานอื่นรันอยู่ ·
   **ก่อน destroy เครื่อง ดึงผลลัพธ์กลับมาก่อนทุกครั้ง** (destroy = หายถาวร ไม่ใช่ stop)
3. ส่งงาน JSON ทุกครั้งต้องผ่าน `python tools/check_format.py <โฟลเดอร์บ้าน>` exit 0 ก่อน
   ห้ามตรวจด้วยตาแทน

```
PDF บ้าน 1 หลัง (แปลงเป็น png รายหน้าแล้ว ใน image/<บ้าน>/)
  ↓ (เสริม) titleblock_ocr.py — OCR คำใบ้ sheet_code/sheet_name ก่อนเข้า Pass 0 (ดูข้อ 1)
  ↓ Pass 0    คัดหน้า (ยังไม่มี runner — ดูข้อ 1)
  ↓ Pass 1    organize.py จัดรูปลงโฟลเดอร์ subtask
  ↓ Pass 1.5  cv_scan.py ตา CV นับ element + ทำ hint
  ↓ Pass 2/2.4 Qwen อ่านแบบ (GPU — ตาม RUNBOOK, แขน 2 vs 2.4a)
  ↓ Pass 2.5  cv_scan.py --pass25 กวาดซ้ำ ทำบัญชีให้ pass 3
  ↓ Pass 3    ถอดระยะ/เหล็ก (prompt พร้อม ยังไม่มี runner — ห้ามลองเอง รอทีม)
  → check_format.py ก่อนส่งทุกครั้ง
```

## ข้อ 1 — Pass 0: คัดหน้า (VLM + OCR ช่วย, ยังไม่มีสคริปต์ยิงจริง)

**สถานะจริง: ไม่มี runner** — ตัวคัดหน้ายังต้องเป็น **VLM (Qwen) เท่านั้น**, prompt อยู่
`tune_ai/t04_Purson/pass0/prompt.md` รูปแบบผลลัพธ์อยู่ `output_example.json` ข้างกัน
**ทดลองเปลี่ยนไปใช้ OCR ล้วนแล้ว (2026-08-29) — ไม่ไหว** OCR อ่านตัวหนังสือในกรอบชื่อแบบเองก็พัง
(easyocr 0/4 หน้า) และต่อให้อ่านออกหมด ก็ยังตอบ `views[]` (หน้านี้กี่รูป ตัดตรงไหน
`also_gridline` ไหม) ไม่ได้เลย เพราะนั่นเป็นการตัดสิน layout ไม่ใช่ text — VLM ยังจำเป็นเสมอ

**สิ่งใหม่ (2026-08-29 คืน): OCR ช่วยเป็นคำใบ้เสริมได้แล้ว** หลังแก้ crop/engine จนแม่นขึ้นมาก
(PaddleOCR PP-OCRv5 lang=th, local ไม่ต้อง API key — วัดจริง 27 หน้า: sheet_code ตรง 24/26)
รันก่อนเรียก VLM:

```bash
python tools/titleblock_ocr.py --dir image/<บ้าน>/
```

จะได้ `<บ้าน>_หน้าNN_titleblock_hint.txt` ข้างรูปที่ OCR อ่านออก (ไม่ใช่ทุกหน้า — บางหน้าไม่มี
สิ่งที่อ่านได้จริงจะไม่มีไฟล์นี้เกิด ปกติ) ถ้ามีไฟล์นี้ ให้แปะต่อท้าย prompt เป็น
`{{TITLEBLOCK_OCR}}` ตามที่ `pass0/prompt.md` อธิบายไว้ — **ช่วยแค่ sheet_code/
sheet_name เท่านั้น ไม่ช่วย views[]** อย่าคาดหวังเกินนี้

วิธีทำวันนี้: (ไม่บังคับ) รัน `titleblock_ocr.py` ก่อนก็ได้ → เอา prompt + รูปทีละหน้า
(+ hint ถ้ามี) ป้อนโมเดล (หรือให้ Claude ทำ) → รวมผลทุกหน้าเป็น `pass0_<บ้าน>.json`
ตามรูปแบบตัวอย่าง

เช็คว่าผ่าน: ทุกหน้ามี entry ครบ ไม่มีหน้าตกหล่น (นับจำนวน entry = จำนวน png) —
**นี่คือด่านอันตรายสุดของสายพาน** หน้าที่คัดผิดจะหายไปทั้งสาย (เคยเกิดจริง:
โครงหลังคาหาย 8 ใน 11 หลัง)

## ข้อ 3 — Pass 1.5: ตา CV (CPU)

```bash
python tools/cv_scan.py --manifest work/<บ้าน>
```

ได้ 3 ไฟล์ต่อหน้า (ใน `cv/` ข้าง images/): `_cv.json` (พิกัด+เลขกำกับ) ·
`_marked.png` (ภาพมาร์คเลข — **ไว้ให้คนดู ไม่ป้อนโมเดล**) · `_hint.txt` (ข้อความ hint)

**เช็คด้วยตาเสมอ (บั๊ก 2 คลาสที่ self-check มองไม่เห็น):** เปิด `_marked.png` 4-5 รูป —
(ก) เลขกำกับไม่ทับกันเอง (ข) ป้ายขาวไม่บังมาร์คจริงบนแบบ (เช่นเลข "1" ของ F1)
เจอเคสใหม่ให้จดหน้านั้นส่งทีม อย่าแก้โค้ดเอง

หน้าที่ CV นับได้ 0 ทั้งที่มีของจริง = คลัง template ยังไม่รู้จักซีรีส์นั้น (ปกติ ไม่ใช่บั๊ก) —
จดไว้ บ้านนั้นแขน 2.4 จะกลายเป็นแขน 2 เองอัตโนมัติ **วัดจริงแล้ว (2026-08-29, 132 หน้า
footing_plan+beam_plan ทั้งคลัง): เฉลี่ยรวม ~51.5% ของ element จริง — 31% ของหน้าได้ 0%,
28% ได้ ≥80%, ที่เหลือกระจายกลางๆ (บางหน้าเกิน 100% เพราะ class ปนกัน ไม่ใช่เจอมากกว่าจริง)**
14 บ้านที่ได้ 0% มี candidate ใหม่ใน `tools/templates/staging/` แล้ว (จาก
`harvest_templates.py`) รอคนตรวจด้วยตาก่อน promote เข้า bank จริง — ห้าม promote เองโดยไม่ดู
(กติกาเดิมของเครื่องมือ ดู `harvest_templates.py` docstring)

ก่อนเริ่มงานทุกรอบ รัน self-check เครื่องมือได้ด้วย:

```bash
python tools/cv_scan.py --demo        # ต้องจบ "OK — self-check ผ่านทุกข้อ"
python tools/merge_guard.py           # ต้องจบ OK
```

## ข้อ 4 — Pass 2/2.4: ยิงโมเดล (GPU — ตาม RUNBOOK เท่านั้น)

**ห้ามเช่าเครื่องเองรอบแรก** — ทำคู่กับพี่ในทีมตาม [`RUNBOOK.md`](RUNBOOK.md) ข้อ 2-4
สรุปสาระ:

- แขนทดลองเหลือ 2: `--arm 2` (ตัวคุม ไม่มี hint) vs `--arm 2.4a` (hint ข้อความ) —
  แขน 2.4b ภาพมาร์คยกเลิกแล้ว (2026-08-29)
- xgrammar (builtin JSON) **เปิดทุก subtask เป็นค่าปริยายแล้ว** (มะขามสั่ง 2026-08-29 —
  เดิมเปิดเฉพาะ plan_beam) ไม่ต้องใส่ flag อะไร · `--grammar-all` กลายเป็น no-op ·
  `--no-grammar` ปิดทั้งหมดไว้ทำ A/B — ถ้าเทียบผลกับรอบเก่าของ subtask อื่นที่ไม่ใช่
  plan_beam ให้จำไว้ว่ารอบเก่าไม่มี grammar ตัวเลข JSON-valid จะกระโดดขึ้นจากตรงนี้ด้วย
  ไม่ใช่จากโมเดลเก่งขึ้นอย่างเดียว
- prompt แต่ละ subtask แยกโฟลเดอร์ตัวเองแล้ว (2026-08-29):
  `tune_ai/t04_Purson/pass2/<subtask>/prompt_<subtask>.md` (ชื่อไฟล์บอกตรงว่า prompt ของอะไร)
  ตัว plan family (`plan_footing`/`plan_beam`/`plan_slab`/`plan_column`) render มาจาก
  `pass2/plan.md` เก็บไว้เป็นต้นแบบ — **แก้กฎร่วมให้แก้ที่ `plan.md` แล้ว re-render ใหม่ทั้ง 4
  ไฟล์ อย่าแก้ไฟล์ลูกตรงๆ จะดริฟท์**
- ตัวรัน: `infer_house_t03.py --house NN --subtask plan_footing --arm 2.4a --cv-dir cv_val`
- ⚠️ ตัวรันนี้**อ่านบ้านจาก train/val.jsonl เท่านั้น** (บ้านที่มี GT แล้ว 01-05, 08, ฯลฯ) —
  บ้านใหม่นอกชุดยังยิงด้วยไฟล์นี้ไม่ได้ ต้องรอทีมเปิด path บ้านใหม่
- อ่านผล: `hint_used` ต้อง true ในแขน 2.4a ของหน้าที่มี sidecar (false = path ผิด หยุดเช็ค) ·
  ตัวตัดสินคือ `recall_printed` ขึ้น **โดยจำนวนหลอนไม่เพิ่ม**
- ใหม่ 2026-08-29 (มะขามสั่ง): prompt ตระกูล plan/gridline/pass3 อนุญาต**วัดสัดส่วน pixel เทียบ
  กริด 2 เส้นที่รู้ `pos_m`** เมื่อ span/ตำแหน่ง dummy line ไม่มีค่าพิมพ์ — ทำ 2 จังหวะเสมอ
  (หา pixel ทั้งหมดก่อน แล้วค่อยแปลงเป็นเมตร) ค่าที่ได้ติดป้าย `span_source: "scaled_from_grid"`
  = **คำนวณมา ไม่ใช่อ่านมา** ยังไม่เคยพิสูจน์ว่า VLM วัด pixel แม่นจริง — ตอนตรวจผลรอบแรก
  ให้เทียบทุกค่า scaled_from_grid กับ GT ก่อนเชื่อ ถ้าคลาดเกิน ~0.1 ม. บ่อย รายงานทีม
  (อาจต้องถอยกฎนี้กลับเป็น `unresolved`) โมเดลต้องเขียนเลข pixel ลง flag ด้วยเสมอ
  (`scaled_between:1,3 P:380 U:142`) — ค่า scaled ที่ไม่มี P/U ในflag = โมเดลไม่ได้วัดจริง ตีตก
- **วิธีวัดว่าโมเดลวัดเป็นไหม โดยใช้ val เดิม (มะขามเคาะ 2026-08-29 — ไม่ต้องสร้าง dataset ใหม่):**
  ยิง val ด้วย `--hide-grid-lines <id,id>` (flag ใหม่ใน `infer_house_t03.py`) — มันซ่อน `pos_m`
  ของเส้นที่เลือกในบล็อก GRID MASTER บังคับให้โมเดลต้องวัดสัดส่วนเอง บนหน้าที่ GT รู้คำตอบจริง
  → เทียบ span ของ element ที่แตะเส้นที่ซ่อน กับ GT ตรงๆ ผลลง `__hide...` แยกโฟลเดอร์
  ไม่ทับผลแขนปกติ **flag นี้ใช้ eval เท่านั้น ห้ามใช้ตอนสกัดจริง**
