# ⭐ วิธีที่ง่ายที่สุด: ดับเบิลคลิกไฟล์เดียว

**ไม่ต้องเปิด terminal · ไม่ต้องพิมพ์คำสั่ง · ไม่ต้องจำอะไรเลย**

ดับเบิลคลิกไฟล์นี้:

```
D:\purson\GO.bat
```

จะขึ้นเมนูให้กดเลข:

```
  1  เชื่อมกับการ์ดที่เช่าเอง  (เลือก+เช่าเครื่องเองที่ vast.ai แล้วเอา instance ID มาใส่)
  2  เช็คสถานะ                (การ์ดยังเปิดอยู่ไหม โมเดลตอบไหม)
  3  เช่าอัตโนมัติทั้งหมด      (ให้สคริปต์หาเครื่องถูกสุด + เปิดโมเดล + เปิดตัวรับงาน ให้เอง)
  4  คืนการ์ด                  (จบงานแล้วต้องกดทุกครั้ง ไม่งั้นเงินเดิน)

  9  เครื่องมือซ่อม            (ทดสอบโมเดล / tunnel / เปิดตัวรับงาน / ปลดงานถอดแบบที่ค้าง)
  0  ออก
```

**วันงานจริงใช้แค่ 2 ปุ่ม: กด `1` (หรือ `3`) ตอนเริ่ม · กด `4` ตอนจบ** — เมนูจัดการที่เหลือให้เอง
(รวมถึงเช็คการ์ดค้าง เปิดหน้าต่างรับงาน และทดสอบว่าโมเดลตอบจริง)

**ข้อ 1 กับ ข้อ 3 ต่างกันตรงใครเลือกเครื่อง:**

| | ข้อ 1 — เชื่อมกับการ์ดที่เช่าเอง | ข้อ 3 — เช่าอัตโนมัติทั้งหมด |
|---|---|---|
| ใครเลือกเครื่อง | เราเลือกเองที่เว็บ vast.ai | สคริปต์หาให้ (ถูกสุดที่ผ่านเกณฑ์, เพดาน $2/ชม.) |
| ต้องเตรียมอะไร | ต้องมี **instance ID** ในมือ (ตัวเลขจากหน้า Instances) | ไม่ต้อง กดแล้วรอ |
| เหมาะกับ | อยากเลือกรุ่นการ์ด/ราคาเอง หรือเช่าค้างไว้ก่อนแล้ว | รีบ ไม่อยากคิด |

> ⚠️ **ตอนเลือกเครื่องเองที่ vast.ai อย่าเลือกเครื่องแบบ Jupyter** — เครื่องกลุ่มนั้นไม่เปิด
> ช่องต่อผ่านพร็อกซีของ vast.ai ระบบจะต่อไม่ติด (เจอจริง 23 ก.ย.) ตอนนี้สคริปต์ลองทั้ง
> ทางตรงและทางพร็อกซีให้แล้ว แต่เลือกเครื่องธรรมดาไว้ก่อนปลอดภัยกว่า

> เมนูจะเตือนเองถ้ากด `0` ออกทั้งที่การ์ดยังเปิดอยู่ (กันลืมคืน = กันเงินเดิน)

### ช่วงเช้า / ล่วงหน้า ~1 ชั่วโมงก่อนพรีเซนต์

**1. เปิด Terminal ที่ 1**

```

```

**2. เช็คก่อนว่ามีการ์ดค้างอยู่ไหม** (ถ้ามี `up` จะไม่ยอมทำงาน)

```

ถ้าเห็นว่ามี instance ค้าง ให้คืนก่อน:

```

**3. สั่งเช่าการ์ด + เปิดโมเดล**

```

```

เลือกรุ่นโมเดลได้ด้วย `--model` (ค่าเริ่มต้นคือ `t03`):

| รุ่น | คำสั่ง | สถานะ |
|---|---|---|
| **destrier** | `--model destrier` | ✅ **ใช้ตัวนี้** — รุ่นที่พิสูจน์แล้วว่าผลถูก (ช้า ~4-5 นาที/หน้า) |
| destrier-sglang | `--model destrier-sglang` | ⚠️ เร็วกว่ามาก แต่**ต้อง merge โมเดลก่อน** ยังไม่เคยรันจริง — อย่าใช้วันงาน |
| destrier-vllm | `--model destrier-vllm` | ⚠️ เงื่อนไขเดียวกับข้างบน |
| t03 | `--model t03` | รุ่นเก่า เก็บไว้เทียบ |

> เมนู `GO.bat` จะถามให้เลือกรุ่นทุกครั้ง — **กด Enter เฉยๆ = destrier** (ตัวที่ถูกต้อง)
> ถ้าเผลอเลือกตัวที่ยังไม่พร้อม ระบบจะเตือนและถามยืนยัน**ก่อน**เช่าการ์ด (ไม่เสียเงินฟรี)

> 🔒 **แก้ให้แล้ว 20 ก.ย.** — `unsloth` ออกเวอร์ชันใหม่ 17 ก.ย. ที่อ่าน adapter ของเราผิด
> (ผลลัพธ์กลายเป็นขยะโดยไม่มี error) ตอนนี้ระบบส่งค่ากันไว้ให้อัตโนมัติทุกครั้งที่เปิดเซิร์ฟเวอร์
> ไม่ต้องทำอะไรเพิ่ม — แค่อย่าไปแก้บรรทัด `UNSLOTH_MOE_LORA_B_LAYOUT` ใน `presentation.py`

ระบบจะทำให้อัตโนมัติ: หาการ์ดว่าง → เช่า → ลง dependency → อัปโหลดโมเดล → เปิดเซิร์ฟเวอร์ → ต่อ tunnel → รอจนพร้อม

**ใช้เวลารวม 20-45 นาที** (ส่วนใหญ่หมดไปกับโหลดโมเดล 70GB) — อย่าปิด terminal ระหว่างรอ

> 💡 **อยากให้โหลดเร็วขึ้นและสะดุดน้อยลง:** ตั้ง `HF_TOKEN` ไว้ในเครื่องก่อนรัน
> ```

> ```
> ตอนนี้เครื่องนี้ยังไม่มีโทเคน จึงโหลดแบบไม่ล็อกอิน ซึ่ง Hugging Face จำกัดความเร็วและ
> **ตัดคอนเนกชันกลางคันเป็นระยะ** (เจอจริง 23 ก.ย. — log ขึ้น `peer closed connection`
> หลายรอบ ระบบรีซูมเองได้ แต่เสียเวลาเพิ่ม) · เอาโทเคนได้ที่
> huggingface.co/settings/tokens (สิทธิ์ Read พอ)

### 💡 อยากไม่ต้องรอโหลดโมเดล 30-45 นาทีทุกครั้ง — `stop` แทน `destroy`

ค่าเช่าแยกเป็นสองก้อน: **ค่าการ์ด** (~$1.3-1.9/ชม.) กับ **ค่าดิสก์** (150 GB ≈ **$0.14/ชม.**)
`destroy` คืนทั้งคู่ · `stop` คืนเฉพาะค่าการ์ด **ดิสก์ยังอยู่พร้อมโมเดล 72 GB ที่โหลดไว้แล้ว**

```
vastai stop instance <id>      ← จบวันแต่จะใช้ต่อพรุ่งนี้
vastai start instance <id>     ← วันพรีเซนต์ พร้อมใน 2-3 นาที
```

ค้างไว้ข้ามคืน 24 ชม. ≈ **$3.4** ถูกกว่าความเสี่ยงที่จะไปเจอเครื่องเน็ตห่วยตอนใกล้ขึ้นเวทีมาก
(23 ก.ย. เจอเครื่องใช้ไม่ได้ 4 ตัวติด กว่าจะได้ตัวที่ดีก็เสียไปเกือบสองชั่วโมง)

> ⚠️ **ข้อควรระวังที่เจอจริง:** `start` ไม่ได้การันตีว่าจะติดทันที — ถ้าเจ้าของเครื่องเอาการ์ด
> ไปให้คนอื่นใช้อยู่ จะขึ้น `Required resources are currently unavailable, state change queued`
> แล้วต้องรอคิว · **ดังนั้นให้ `start` ล่วงหน้าอย่างน้อย 1 ชั่วโมงก่อนพรีเซนต์ ไม่ใช่ก่อน 5 นาที**
> ถ้ารอแล้วไม่ขึ้นจริงๆ ยังกลับไปเช่าใหม่ทัน

## ถ้ามีปัญหา

| อาการ | ทำยังไง |
|---|---|
| `cd` ไม่เจอโฟลเดอร์ | ใช้ `cd D:\purson` (อย่าพิมพ์ path ภาษาไทย) |
| `up` บอกว่ามี instance ค้าง | `python presentation.py down` ก่อน แล้วค่อย `up` ใหม่ |
| ปุ่มกดแล้วไม่มีอะไรเกิดขึ้น | เช็คว่า terminal ที่ 2 (`worker.py`) ยังเปิดอยู่ไหม |
| ค้างที่ "รอ worker" นานเกินไป | เช็คว่า `worker.py` รันอยู่จริง + `python presentation.py status` |
| Tunnel หลุด | `python presentation.py tunnel` |
| โมเดลไม่ตอบเกิน 10 นาที | บั๊กข้อ 1 ด้านล่าง — เช่าเครื่องใหม่ หรือข้ามไปโชว์ผลที่เตรียมไว้ |
| ไม่แน่ใจว่าการ์ดยังเปิดอยู่ไหม | `python presentation.py status` |
| ค้างที่ `mkdir -p /workspace` เงียบๆ นานเกิน 1 นาที | เครื่องเช่ามีอาการ — `status` แล้วดูช่อง `actual_status` ถ้าเป็น `offline` ให้คืนแล้วเช่าใหม่ อย่าฝืนรอ |
| `status` ขึ้น `actual_status: offline` แต่ยังคิดเงินอยู่ | เครื่องหลุดจาก vast.ai — กดข้อ `4` คืนทันที แล้วเช่าใหม่ (ข้อ `3` เร็วสุด) |
| เจอเครื่องเจ๊งซ้ำๆ (ต่อไม่ติด / เน็ตช้า) | **ไม่ต้องทำอะไร** — ข้อ `3` ลองเองได้ถึง 3 เครื่อง คืนตัวที่เจ๊งให้เอง แล้วจำไว้ไม่เช่าซ้ำ (ดูหัวข้อถัดไป) |

| ตี๊ด-ตี๊ด-ตี๊ดดด (ไล่ขึ้น) | **โมเดลพร้อมรับงานแล้ว** — กลับมาได้ |
| ตี๊ด-ตี๊ดดด (สั้น สูง) | ถอดแบบงานหนึ่งเสร็จ |
| ตื้ด-ตื่อออ (ต่ำ ไล่ลง) | มีอะไรล้ม ต้องมาดู |

อยากลองฟังก่อน: เมนูข้อ `9` → `7`

**ตอนขึ้นเวทีจริงถ้าไม่อยากให้ไมค์รับเสียงไปด้วย** พิมพ์บรรทัดนี้ก่อนเปิดเมนู:

```
set PURSON_QUIET=1

## 🚫 บัญชีดำ — เครื่องที่พิสูจน์แล้วว่าใช้ไม่ได้

23 ก.ย. 69 เช่าเครื่องเจ๊งติดกัน 4 เครื่อง (ต่อ ssh ไม่ติดบ้าง เน็ต 6 MB/s บ้าง) เสียเวลาไปชั่วโมงกว่า
เพราะทุกครั้งที่ล้ม ต้องกลับมากดเมนูใหม่เอง แล้วก็มีสิทธิ์สุ่มได้เครื่องเดิมอีก

ตอนนี้ **ข้อ `3` จัดการให้เองทั้งหมด**:

1. เจอเครื่องเจ๊ง → **คืนทิ้งทันที** (ไม่ปล่อยให้เงินเดิน)
2. จดเครื่องนั้นไว้ในบัญชีดำ
3. ไปลองเครื่องถัดไปต่อเอง — ลองได้สูงสุด 3 เครื่องต่อการกด 1 ครั้ง

นับเป็น "เจ๊ง" เมื่อ: ต่อ ssh ไม่ติดใน 15 นาที · ส่งไฟล์ค้าง · หรือ **โหลดโมเดลจะใช้เกิน 60 นาที**
(เครื่องดีใช้ 20-30 นาที — เปลี่ยนเครื่องถูกกว่ารอเสมอ)

**เจอเครื่องห่วยเองก็บอกได้:** ตอนกดข้อ `4` คืนการ์ด มันจะถามว่า "เครื่องนี้มีปัญหาไหม?"
ตอบ `y` แล้วพิมพ์สั้นๆ ว่าเป็นอะไร — รอบหน้าจะไม่เจอเครื่องนี้อีก

| อยากทำอะไร | ไปที่ |
|---|---|
| ดูว่าแบนเครื่องไหนไว้บ้าง | เมนูข้อ `9` → `5` |
| ล้างบัญชีดำ (เผื่อโฮสต์ซ่อมแล้ว) | เมนูข้อ `9` → `6` |

> รายชื่ออยู่ในไฟล์ `blacklist.json` ข้างๆ สคริปต์ — เปิดอ่านเองได้ แก้มือก็ได้

## ⚠️ ข้อจำกัดที่ต้องรู้

### 1. ยิงพร้อมกัน 2 งาน → เซิร์ฟเวอร์ค้างทั้งระบบ

ถ้ามี 2 คำขอเข้าโมเดลพร้อมกัน เซิร์ฟเวอร์จะค้างสนิทนานหลายชั่วโมง ไม่ตอบแม้แต่คำขอเช็คสถานะ

**วิธีป้องกัน:** ให้มีคนเดียวกดปุ่มทีละครั้ง **รอผลเสร็จก่อนกดครั้งถัดไปเสมอ**

> อาการนี้เกิดจากโมเดลวนซ้ำไม่จบแล้วบล็อกงานอื่น · **31 ส.ค. แก้ต้นเหตุการวนซ้ำไปแล้ว** (เลิกใช้ greedy decoding
> ตามที่ Qwen แนะนำ) อาการน่าจะดีขึ้นมาก แต่ **ยังไม่ได้ทดสอบยิงพร้อมกันซ้ำหลังแก้** — ยังห้ามไว้ก่อน

### 2. แปลนคานยังอ่านไม่แม่น

ผลวัดล่าสุด (31 ส.ค. บ้านไทยพอเพียง3 หน้า 26/27 — บ้านที่โมเดลไม่เคยเห็น):

| หน้า | ผล |
|---|---|
| **แปลนฐานราก** | อ่านถูก **ทุกตัว ทุกตำแหน่ง** (F4/F7/F8/F11 ครบ 12 ฐาน) |
| **แปลนคาน** | รู้จักชื่อคาน 89% แต่วางตำแหน่งผิดบางท่อน · พื้นสำเร็จรูปหายทั้งหมด |

**คำแนะนำวันสาธิต:** โชว์ **หน้าแปลนฐานราก / ตารางเหล็ก / รูปตัด** จะได้ผลน่าประทับใจและตรงความจริง
ถ้ามีคนถามเรื่องแปลนคาน พูดตรงๆ ได้เลยว่า *"ยังอยู่ระหว่างพัฒนา รุ่นต่อไปกำลังแก้จุดนี้"*

### 3. ความเร็ว 4-5 นาทีต่อหน้า — **แต่หน้าที่อัดผังมาหลายผังใช้ได้ถึง 25 นาที**

บ้านเต็มหลัง (~38 งาน) ราว 3 ชั่วโมง — เตรียมผลล่วงหน้า หรือโชว์สดแค่ 1-3 หน้าเพื่อสาธิตกลไก

**เวลาต่อหน้าไม่คงที่ มันขึ้นกับว่าหน้านั้นมีของให้เขียนเท่าไร** วัดจริงจากงานสาธิต 23 ก.ย.

| ความยาวคำตอบ | เวลาที่ใช้ |
|---|---|
| 511 ตัวอักษร | 46 วินาที |
| 827 | 59 วินาที |
| 2,059 | 3.6 นาที |
| 3,012 | 4.6 นาที |
| ชนเพดาน 6,000 token (~15,000-18,000 ตัวอักษร) | **~25 นาที** |

โมเดลเขียนได้ราว **11 ตัวอักษรต่อวินาที** คงที่ ดังนั้นเวลา = ความยาวคำตอบ ไม่ใช่ความยากของแบบ

**หน้าที่จะกินเวลานาน** คือหน้าที่มีผังเต็มมากกว่าหนึ่งผังในแผ่นเดียว เช่น S-01 ของบ้าน
ครอบครัวไทยเป็นสุข 2 ที่รวมแปลนฐานราก/ตอม่อ/เสา/คาน/พื้น **กับ** แปลนโครงหลังคาไว้ด้วยกัน
มีมาร์คหลายสิบตัว (B1 B1A B2 B3 B4 C1 F1 F2 S1-S4 RB1 RB2 CN CX...) โมเดลต้องเขียนออกมาทุกตัว

> **บนเวทีให้เปิดหน้าแบบดูก่อนเสมอ** — ถ้าเห็นผังเต็มสองผังในแผ่นเดียว บอกคนดูไว้ล่วงหน้าเลยว่า
> หน้านี้ใช้เวลานานกว่าปกติเพราะมีของเยอะ ดีกว่ายืนเงียบรอ 20 นาทีแล้วให้คนสงสัยว่าค้างหรือเปล่า
> · worker ตั้งเพดานรอไว้ 45 นาทีต่อหน้า (`PAGE_TIMEOUT_S`) ยังไม่เคยมีหน้าไหนไปถึง
