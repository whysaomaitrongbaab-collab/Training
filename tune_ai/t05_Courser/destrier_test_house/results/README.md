# ผลการทดสอบ Destrier (t05) — เรียงตามลำดับที่ทำจริง

| โฟลเดอร์ | คืออะไร |
|---|---|
| `01_op04_sampling_ผ่าน` | **การวัด recall จริงที่ใช้ได้** — decode ด้วย temp 0.7 / top_p 0.8 / top_k 20 (ค่าที่ Qwen แนะนำ). มี `grid_master.json`, `gt_beam.json`, `gt_footing.json`, ผลตัดสิน (`gt_judge_full.json`), เวลาที่ใช้ (`timings.json`) |
| `02_op04_greedy_พัง` | รันแบบเดียวกันแต่ใช้ **greedy decoding** — พังคือ 0% recall (โมเดลหลุดพ่นภาษาจีนยาว) เก็บไว้เทียบให้เห็นว่าทำไม sampling ถึงจำเป็น |
| `03_gpuA_เช่าตัวแรก_ช้า` | log การเช่าการ์ดจอตัวแรก (config A) — ช้า/มีปัญหา ไม่ใช้ต่อ |
| `04_gpuB_เช่าที่ใช้ได้` | log การ์ดจอตัวที่ใช้งานได้จริง (config B) |
| `05_e2e_pass_ระบบเต็ม` | ทดสอบทั้งระบบ pass0 → pass1 → pass1.5 → pass2 → pass2.5 รวดเดียว (`job_full.json`) — ผลดิบของแต่ละหน้าอยู่ใน `result.files[].json` ของไฟล์นั้น |
| `06_endpoint_ทดสอบทีละหน้า` | ทดสอบยิงทีละหน้า (page09/10/12) ผ่าน endpoint ตรงๆ ก่อนต่อเข้าระบบ pass เต็มรูป — โฟลเดอร์ย่อย `loose_เก่ากว่า/` คือรอบทดสอบก่อนหน้านั้นอีก |
| `07_smoke_test_แรกสุด` | smoke test แรกสุด ยิง gridline กับ plan_beam ทีละไฟล์ ก่อนจะมีระบบ pass |

ไล่อ่านจากล่างขึ้นบน (07 → 01) คือลำดับที่ทำจริง: smoke เดี่ยวๆ → ทีละหน้า → เช่า GPU → e2e ทั้งระบบ → วัด recall จริง (greedy พังก่อน แล้วแก้เป็น sampling ถึงผ่าน)
