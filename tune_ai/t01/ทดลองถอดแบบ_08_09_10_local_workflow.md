## ตัวกรองหน้า — ใช้ t03 Pass 2 แทนตัวกรองเดิมของ t01

สคริปต์ `extract_house01_local.py` เดิมกรองด้วย `KEEP_PATTERNS = {plan, section, roof_plan,
side_profile, gridline}` (คิดขึ้นตอนรอบ t01 เอง) แต่ t03 (`tune_ai/t03/pass_design.csv` +
`README.md`) วิเคราะห์ไว้ละเอียดกว่าว่า Constistant **อ่านจริง 7 pattern** (Pass 2):

```
gridline, plan, section, schedule, notes, material_list, soil_boring_log
```

(`roof_plan`/`side_profile` ถูกจัดเป็น Pass 3 — ยังไม่มีอะไรใน Constistant อ่าน) — **รอบนี้ยึด
t03 Pass 2 แทน** (มะขามสั่งเปลี่ยนระหว่างคุย 2026-08-24) `extract_houses_local.py` แก้
`KEEP_PATTERNS` ตามนี้แล้ว

**บั๊กที่เจอและแก้ระหว่างทาง:** `CLASSIFY_PROMPT` เดิมของ t01 (สืบทอดมาจาก
`extract_house01_local.py`) มีตัวเลือกให้โมเดลจัด pattern แค่ 14 จาก 16 ตัวจริงใน
`primary_rawjson_schema.md` — **ขาด `soil_boring_log` และ `bbs_schedule`ไปเลย** ถ้าไม่แก้
หน้าที่เป็น soil boring log จะไม่มีทางถูก classify ถูก ทั้งที่อยู่ใน Pass 2 ที่ต้องการ — เพิ่มสอง
pattern นี้เข้า prompt แล้ว (`ALL_PATTERNS` ก็เพิ่มตามให้ครบ 16)

**ขอบเขตที่ยังไม่ทำ (บอกตรงๆ ไม่กลบ):** ยังใช้ prompt เดียว (`PROMPT_SHORT`, generic "อ่านทุก
อย่างในหน้า") สำหรับหน้าที่ผ่านกรองทุกแบบ — **ไม่ได้ใช้ prompt เฉพาะทางต่อ subtask ของ t03**
(`pass2_used/gridline.md`, `plan.md`, `section.md`, `schedule.md`, `notes.md`,
`material_list.md`, `soil_boring_log.md` — 7 ไฟล์ที่ t03 เขียนไว้แต่ยังไม่เคยรันสักตัว) นั่นคือ
งานของ t03 เต็มรูปแบบ (Pass 0→1→2/3 พร้อม crop รูปต่อ view) ซึ่งใหญ่กว่านี้มากและยังไม่มีอะไรถูก
ทดสอบเลยสักขั้น — งานวันนี้แค่ **ยืมนิยาม "หน้าไหนสำคัญ" จาก t03 มากรอง** ก่อน extract ด้วยวิธี
เดิมของ t01 เท่านั้น

## Phase 1 — ทดสอบสั้นก่อนเสมอ (ทำไปแล้ว 2 รอบ, ยืนยันด้วยตัวเลขจริง)

```bash
cd "tune_ai/t01"
python extract_houses_local.py --model tuned --houses 08 --limit 3
```
ผล: server start/health OK, classify cache ใช้ซ้ำได้ (รอบ 2 ไม่เรียกโมเดลซ้ำ), filter ใหม่คัดถูก
(หน้า03 schedule เข้าเกณฑ์ Pass2 ที่รอบก่อนไม่เคยเข้า), shutdown สะอาด

## Phase 2 — รันเต็ม (ยังไม่ทำ — รอ Phase 0 ข้อ 4-6 ก่อน)

```bash
python extract_houses_local.py --model tuned --houses 08 09 10
# แล้วค่อยรัน base แยก (GPU ตัวเดียว รันพร้อมกันไม่ได้):
python extract_houses_local.py --model base --houses 08 09 10
```
resume-safe ทั้ง classify (`_classify.json`) และ extract (ข้ามไฟล์ `_ai.json` ที่มีอยู่แล้ว) —
หลุดกลางทาง (เครื่องหลับ, restart) รันคำสั่งเดิมซ้ำได้ ไม่เสียงานที่ทำไปแล้ว

ผลลัพธ์แยกโฟลเดอร์: `tune_ai/t01/ผล_08_09_10/<tuned|base>/<08|09|10><house_name>/`

## Phase 3 — (ทางเลือก, ยังไม่ทำ) เทียบกับ ground truth

## ข้อจำกัดที่รู้อยู่แล้ว บอกตรงๆ

- **tuned vs base คนละ quant level** (Q4_K_M 21.2GB vs IQ2_XXS 10.8GB) — ไม่ใช่ apples-to-apples
  เป๊ะ ผลต่างที่เห็นอาจมาจาก quant บางส่วน ไม่ใช่จากการทูนล้วนๆ ถ้าต้องการเทียบแฟร์กว่านี้ต้องโหลด
  base ระดับ Q4_K_M เพิ่ม (~21GB, ยังไม่ได้โหลด)
- **prompt เดียวสำหรับทุก pattern ที่ผ่านกรอง** — ไม่ใช่ per-subtask prompt แบบ t03 (ยังไม่มีอะไร
  ใน t03 ถูกรันจริง)
- ground truth ของบ้าน 08/09/10 ยังไม่ผ่านรีวิวเนื้อหา (ย้ำอีกรอบ เพราะสำคัญ)
