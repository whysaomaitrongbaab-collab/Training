💡 Logic Blueprint: End-to-End Multi-Pass Architecture
▼

🎯 สิ่งที่กระบวนการนี้ทำ (What it does)

ถอดแบบก่อสร้างสถาปัตย์-วิศวกรรมไทยแบบ Multi-Pass ทีละสเต็ป โดยนำภาพมาจำแนกประเภทหน้า (Pass 0) $\rightarrow$ ครอปรูปแยกมุมมอง (Pass 1) $\rightarrow$ สแกนสัญลักษณ์ด้วย CV (Pass 1.5) $\rightarrow$ ดึงผังกริด (Pass 2 Grid) $\rightarrow$ สกัดชิ้นส่วนคาน/ฐานราก/เหล็กเสริม (Pass 2 Subtasks) $\rightarrow$ เทียบสเกลจริง (Pass 3)

⚙️ ทำไมต้องแยกหลาย Pass (Why Multi-Pass)

แบบแปลน 1 หน้ามีความหนาแน่นของข้อมูลสูงมาก ถ้าสั่งให้ AI ดึงทุกอย่างในครั้งเดียว (Zero-Shot) จะเกิดอาการหลอน (Hallucination) และสับสนพิกัด การแยกให้ AI รู้ผังกริด (GRID MASTER) ก่อน จะทำให้การระบุตำแหน่งคานแม่นยำขึ้นกว่า 80%

⚠️ กับดักที่เคยพัง (Known Traps)

1. Temperature 0 (Greedy) พัง: หลุดภาษาจีนและวนลูปจนชนเพดาน Token (ต้องใช้ 0.7)
2. Token Limit ชนเพดาน: ต้องเปิดใช้ Salvage Logic เพื่อกู้ชิ้นส่วนที่ตัดกลางคัน
3. Negative Dimension: ตัวเลขขนาดติดลบต้องถูกล้างทิ้ง

🎯 การประกอบ Prompt (Assembly Rule)

Prompt ที่โมเดลเห็นถูกประกอบด้วย 3 ส่วนหลักแบบ Byte-identical:
1. COMMON BLOCK: กฎร่วม สัจธรรมเรื่องหน่วย ห้ามเดา
2. PROMPT BLOCK: นิยามฟิลด์ JSON ของ Subtask นั้น ๆ
3. GRID MASTER TAIL: แกน X, Y ที่อ่านได้ นำมาปะท้ายเพื่อให้โมเดลผูกช่วงคาน

📐 สัญญาข้อมูล (Output Contract)

Constistant Adapter รับเฉพาะฟิลด์ตามข้อตกลง finetune_output_contract เท่านั้น ถ้า AI ตอบผิดรูปทรง เช่น ไม่มี grid_ref_start/end คานตัวนั้นจะกลายเป็น 0 ใน BOQ ทันที

✂️ Pass 1: View Cropping (`organize.py`)

ทำงานบน Local CPU (0 บาท) แยกแผ่นงานที่มีหลาย View เป็นรูปภาพย่อย เพื่อคุมความหนาแน่นของ Visual Token ให้ตรงกับขนาด 6912*1024 ที่โมเดลเคยเรียนมา

🎯 Pass 1.5: Template Matching (`cv_scan.py`)

ใช้ OpenCV MatchTemplate สแกนหาสัญลักษณ์ฐานราก/เสา/คาน เพื่อสร้างดัชนีกล่อง #n และส่ง Hint ไปช่วย AI ใน Pass 2 ถ้าหาไม่เจอจะ Fallback ให้ AI อ่านเอง

📐 Pass 3: Fit พิกเซลต่อเมตร

นำจุดหมุด (Grid Ref ที่ AI อ่านได้ + พิกัด CV Bounding Box) มาคำนวณ Fit หาอัตราส่วนพิกเซลต่อเมตร เพื่อตรวจสอบว่าขนาดตัวอาคารที่ AI ถอดได้ สอดคล้องกับพิกัดจริงหรือไม่

📏 Vector Ruler จาก PDF

สกัดเวกเตอร์เส้นตรงจากไฟล์ PDF โดยตรงเพื่อหาแนวเส้นกริด เป็นไม้บรรทัดบริสุทธิ์ที่รันได้โดยไม่ต้องพึ่งพา AI หรือ CV

🛡️ D3 Rule: Report-Only

Pass 3 ทำหน้าที่เป็น รายงานตรวจสอบอย่างเดียว (Report-Only) จะไม่มีการเขียนทับหรือแก้องค์ประกอบที่ AI สกัดได้ใน Pass 2 เด็ดขาด เพื่อป้องกันความคลาดเคลื่อนสะสม

📌 กฎเหล็กทางวิศวกรรมที่ค้นพบ (Critical Engineering Rules)

  • ห้ามใช้ Greedy (Temperature 0): ทำให้ Qwen หลุดพ่นอักษรจีนและวนลูปจน Token ชนเพดาน ต้องใช้ Temperature 0.7 เสมอ
  • ปิด Thinking (CoT): ต้องส่ง chat_template_kwargs: {"enable_thinking": False} เสมอ ไม่เช่นนั้นความคิดในแท็ก <think> จะกินงบ Token จน JSON ขาดครึ่ง
  • Salvage Truncated JSON: เมื่อ Token ชนเพดาน 6,000 อย่าโยนไฟล์ทิ้ง ให้ตัดย้อนกลับไปหาชิ้นส่วนสมบูรณ์ตัวสุดท้ายแล้วปิด Bracket แทน (กู้คืนได้หลายสิบชิ้นส่วน)
  • GRID MASTER มาก่อนเสมอ: แปลนคานจะหาความยาวช่วงไม่ได้เลยถ้าไม่มีผังกริด ดังนั้น Pass 2 ต้องยิง Gridline ให้เสร็จก่อนแล้วส่งต่อให้ทุกแปลน
