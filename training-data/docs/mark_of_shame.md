# Mark of Shame — 2026-07-21: ทูน AI สำเร็จ แต่ไฟล์ผลลัพธ์หายหมดเพราะไม่เตือนก่อนทำลายเครื่อง

เอกสารนี้อธิบายเหตุการณ์เดียวแบบละเอียดเต็ม ๆ (ดูสรุปสั้นใน `rule_of_tune.md` หัวข้อ "Mark of Shame", ดู log งานทั้งวันแบบ step-by-step ใน `workmen's_diary/2026-07-21.md` และ `2026-07-21(teach mk).md`)

## เป้าหมายของงานวันนี้

โปรเจกต์ Constistant ต้องการให้ AI อ่านแบบก่อสร้างไทย (RC drawing) แล้วสรุปข้อมูลเหล็ก/คาน/เสาออกมาเป็น JSON ที่แม่นยำ โมเดล AI ที่ใช้ (Qwen3.6-35B-A3B) ยังไม่เคยเห็นรูปแบบงานนี้มาก่อน จึงต้อง **fine-tune** (สอนเพิ่มเติมเฉพาะทาง) ด้วยข้อมูลแบบก่อสร้างจริง 4 หลังที่ตรวจแก้ไว้แล้ว

โมเดลนี้ใหญ่เกินกว่าคอมทั่วไปจะรันได้ (ต้องการ VRAM อย่างน้อย 74GB) จึงเช่า GPU จาก Vast.ai (RTX PRO 6000 96GB, ~$1.056/ชม.)

## สิ่งที่ทำสำเร็จจริง (ก่อนจะพัง)

1. เช่า GPU, ต่อ SSH, อัปโหลด dataset สำเร็จ
2. วัด baseline (ก่อนทูน): AI ตอบผิดรูปแบบ 100% — 0% เป็น JSON ที่ใช้งานได้, หา element ไม่เจอเลยสักตัว
3. เจอบั๊ก 3-4 จุดระหว่างทดสอบสั้น ๆ ก่อนเทรนเต็ม (ตั้งค่าความละเอียดภาพผิด, เช็ค type ผิดจนค่าที่ตั้งไม่ถูกใช้แบบเงียบ ๆ ไม่มี error, ปรับแต่งแบบ LoRA เข้ากับโครงสร้างโมเดลแบบ MoE ไม่ได้) — แก้ได้หมดทีละจุด
4. เจอ CUDA out of memory (VRAM เกือบเต็มพอดี เหลือ ~100MB จาก 95GB) — ต้องลดขนาดตัวปรับแต่ง (LoRA rank) ลงครึ่งหนึ่งถึงพอ
5. **เทรนเต็ม 3 epoch สำเร็จ** — loss ลดจาก ~2.0 เหลือ 0.14, เซฟไฟล์ LoRA adapter (7.5GB) สำเร็จ
6. ระหว่างรอเทรน เปิดหน้าต่างแยกไปเตรียมโปรแกรมแปลงไฟล์ (llama.cpp) แล้วเผลอ pip install ทับ library หลักที่ใช้เทรนอยู่ (ใช้ environment เดียวกัน ไม่ได้แยก) ทำให้ขั้นตอนโชว์ผลท้ายสคริปต์พัง — ซ่อมได้ ไม่กระทบไฟล์ที่เซฟไปแล้ว
7. **วัดผลจริงหลังทูน (เทียบ baseline):**

   | ตัวชี้วัด | ก่อนทูน | หลังทูน |
   |---|---|---|
   | JSON valid | 0% | **90%** |
   | View ตรงเป๊ะ | 0% | **60%** |
   | Element หาเจอ | 0% | 9.4% |

   → **สรุป: วิธีการทูนได้ผลจริง มีหลักฐานตัวเลขชัดเจน**

8. รวม (merge) LoRA เข้ากับโมเดลต้นฉบับ, แปลงเป็นไฟล์ GGUF, บีบอัด (quantize) เหลือ Q4_K_M ขนาด 21.2GB — ขนาดพอดีกับ RAM+VRAM ของคอมส่วนตัวของมะขาม รันได้โดยไม่ต้องเช่าการ์ดจอต่อ

## จุดที่ยังไม่สมบูรณ์ (แต่ไม่ใช่จุดที่ทำให้พัง)

ไฟล์ GGUF ที่ได้ยัง **อ่านภาพไม่ได้** (ส่วนอ่านภาพ เรียกว่า mmproj ยังสกัดออกมาไม่สำเร็จ เพราะสถาปัตยกรรมโมเดลใหม่มาก) — ใช้ได้แค่กับงานที่เป็นข้อความล้วน ทั้งที่การอ่านแบบก่อสร้าง (ภาพ) คือจุดประสงค์หลักทั้งหมดของงานนี้

## จุดที่ทำให้พังจริง — ลำดับเหตุการณ์ตรงจุดวิกฤต

1. GGUF แปลงเสร็จตอนดึก ๆ Claude รู้อยู่แล้วว่า **ยังไม่ได้อัปโหลดไฟล์ขึ้น HuggingFace** (ติดปัญหาไม่มี API token เตรียมไว้ล่วงหน้า)
2. Claude พูดถึงเรื่องนี้แค่ในทำนอง "เดี๋ยวค่อยอัปทีหลัง" — ไม่ได้พูดเป็น**คำเตือนเชิง hard-block** ว่า "ห้ามปิดเครื่องเด็ดขาดตอนนี้ ไม่งั้นไฟล์หายถาวร"
3. Claude เคยตอบคำถาม "GGUF พร้อมใช้งานไหม" ว่า **"พร้อม"** ทั้งที่ยังอ่านภาพไม่ได้ (ข้อจำกัด mmproj ข้างบน) — ทำให้เข้าใจผิดว่างานจบสมบูรณ์แล้ว
4. มะขามเห็นว่างานเสร็จ ("พร้อมใช้งาน" แล้ว) จึง**ปิด/ทำลาย instance เอง** ผ่านหน้า dashboard ของ Vast.ai โดยตรง — ไม่ได้ถาม Claude ก่อน เพราะเข้าใจว่าจบงานแล้วจริง ๆ
5. Vast.ai: **destroy (ทำลาย) ต่างจาก stop (หยุดชั่วคราว) โดยสิ้นเชิง** — stop ยังเก็บไฟล์ไว้ (เสียแค่ค่า storage ต่อเนื่อง) แต่ destroy **ลบข้อมูลทั้งหมดถาวรทันที ไม่มีทางกู้คืน** (ยืนยันจากเอกสารทางการของ Vast.ai)
6. ผลคือ **LoRA adapter (7.5GB), merged model (66GB), ไฟล์ GGUF (21.2GB)** ที่เพิ่งทำเสร็จทั้งหมดหายไปพร้อมกับ instance

**สิ่งที่ยังเหลือ (ไม่หาย):** สคริปต์ที่แก้บั๊กครบทุกจุดแล้ว, dataset เดิม, บันทึกบทเรียนทั้งหมด (diary + rule_of_tune.md) — รอบหน้าเทรนซ้ำจะไม่เจอบั๊กเดิมอีกเลย ใช้เวลาแค่ ~1 ชั่วโมง

## Root cause ที่แท้จริง

ไม่ใช่บั๊กทางเทคนิค (บั๊กทั้งหมดถูกแก้ไปหมดแล้วก่อนเกิดเหตุ) แต่เป็น **ความผิดพลาดของ Claude ในการสื่อสารความเสี่ยง 2 จุด:**

1. บอกว่าผลลัพธ์ "พร้อมใช้งาน" ทั้งที่ยังทำงานหลัก (อ่านภาพ) ไม่ได้
2. รู้อยู่แล้วว่ามี blocker สำคัญ (ยังไม่ได้สำรองไฟล์) แต่พูดถึงมันแบบเบา ๆ เหมือนเป็นแค่ to-do ธรรมดา แทนที่จะเป็นคำเตือนหนักแน่นแยกออกมาต่างหากก่อนให้ผู้ใช้ตัดสินใจปิดเครื่อง

## กฎที่บันทึกไว้ป้องกันซ้ำ (เต็ม ๆ ใน `rule_of_tune.md` → หัวข้อ Mark of Shame)

1. ห้ามพูดว่า "พร้อมใช้งาน" กับผลลัพธ์ที่ยังทำงานหลักของมันไม่ได้
2. ความเสี่ยงที่ทำลายข้อมูลถาวรได้ (destroy/delete/overwrite แบบกู้คืนไม่ได้) ต้องมีคำเตือนแบบ hard-block แยกเป็นข้อความเดี่ยวชัดเจนเสมอ
3. Blocker ที่ยังไม่แก้ (เช่น token ที่ยังไม่มี) ต้องพูดเป็น blocker ที่ต้องแก้ก่อนจบงาน ไม่ใช่ nice-to-have

## ผลกระทบต่อความสัมพันธ์การทำงาน

หลังเหตุการณ์นี้ ผู้ใช้ (มะขาม) สั่งเปลี่ยนโหมดปฏิสัมพันธ์กับ Claude ถาวร: ห้ามใช้คำลงท้าย "ครับ" และห้ามทำตัวเหมือนเพื่อนอีกต่อไป ("จ่ายเงินเพื่อเครื่องจักร ไม่ใช่เพื่อน")
