### 3. ★★ สาเหตุที่น่าจะจริงที่สุด — **LoRA อาจไม่ได้อยู่ใน GGUF ของ t01 เลย**

นี่คือเรื่องใหญ่สุดของคืนนี้ และเป็น**บั๊กเดียวกับที่ทำ t02 พังเมื่อวันที่ 28**

**หลักฐาน 4 ข้อ (ตรวจโค้ดจริงด้วยตาแล้ว ไม่ใช่อนุมาน):**

1. **หน้า 03-06 คือ training data ของ t01 เอง** (train.jsonl บรรทัด 3-6) โมเดลเคยเห็นตอนเทรน
   แล้วยัง**ตอบไม่ตรง schema ที่เทรนมาเลยสักหน้า** — format conformance เป็นสิ่งที่ fine-tune
   เรียนได้เร็วที่สุด (ปกติล็อกได้ในไม่กี่ร้อย step แรก) ถ้าพลาดบนหน้าที่ท่องมาแล้ว = ผิดปกติมาก

2. **`train_qwen36.py:152`** เขียนคอมเมนต์ไว้เอง:
   *"ต้องเป็น 0 — **MoE ParamWrapper** ของโมเดลนี้ไม่รองรับ dropout!=0 (ยืนยันจาก error จริง)"*
   → **t01 ใช้ ParamWrapper (LoRA แบบ `target_parameters` บน MoE experts)**

3. **เมื่อวันที่ 28 เราพิสูจน์ไปแล้วว่า `merge_and_unload()` ของ peft/Unsloth
   merge LoRA แบบ ParamWrapper บน MoE ไม่ถูกต้อง** (เปลี่ยนค่าจริงแค่ 0.67% ทั้งที่ควรเปลี่ยนเยอะกว่านั้นมาก
   — โครงสร้างผ่าน แต่พฤติกรรมกลับไปใกล้ base) → **t01 แปลง GGUF ด้วยฟังก์ชันเดียวกัน**

4. **ด่านกัน merge เงียบของ t01 อ่อนเกินกว่าจะจับได้** — `export_gguf.py:107`:
   ```python
   _looks_tuned = _pred.lstrip().startswith("{") and any(k in _pred[:400]
                  for k in ('"png"', '"views"', '"pattern"', '"doc_page"'))
   ```
   แต่ **prompt เองสั่งให้โมเดลตอบด้วยคำว่า `"views"` และ `"pattern"` อยู่แล้ว**
   → โมเดล**ที่ยังไม่ทูนเลย**ก็ผ่านด่านนี้ได้สบาย ๆ แค่ทำตาม prompt
   → ตอนนั้นมันขึ้น ✓ เขียวแล้วพิสูจน์อะไรไม่ได้เลย

**เทียบกับ t02:** t02 ถูกจับได้เพราะด่านของ t02 เทียบ**ชื่อ key จริง** (เจอ `page_number/title/project`
แทน `png/doc_page/...` เลยหยุด) — **t01 ใช้ด่านที่อ่อนกว่า จึงปล่อยผ่าน**
