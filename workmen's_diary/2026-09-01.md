  found real bugs, most severe: `sanitize_elements()` in `worker.py` rejected any negative

  beam `GB1(-0.50)`). Also found: `requeue_stale()` uses `claimed_at` instead of `updated_at`
  as the heartbeat, so a real ~75-80min job gets requeued and double-run by a second worker
  under the 45min stale threshold. Neither fixed yet — reported to Makham, not yet actioned.

  despite the key matching the registered vast.ai account key exactly (verified fingerprint) —
  matches the documented "host มีอาการ = destroy แล้วเช่าใหม่" lesson. Destroyed, re-rented.
- Full teardown cycle done twice today (`presentation.py down`, verified 0 billed instances

**Task 2 — pass3: วัดระยะจริงจากพิกเซล (`server/purson-worker/pass3_measure.py`, ใหม่)**
- โจทย์มะขาม: เอาผล pass1.5/2.5 มาวัดต่อ — หาจุดศูนย์กลางจากมุมไปมุมของ element แล้ววัด
  pixel เทียบ grid master ("นับ pixel from grid A-B เทียบ grid master แล้ววัดคานสู่คาน")
- **วิธีที่เลือก — ไม่ต้อง detect เส้นกริดในภาพเลย:** ใช้ "หมุด" = element ที่มีทั้ง `grid_ref`
  (โมเดล pass2 อ่านได้) และ `cv_position` (CV เห็น) → คู่ (pixel, เมตร) ที่รู้ทั้งสองฝั่ง →
  least-squares fit 2 แกนแยกกัน `px = a*m + b` → ได้ px ต่อเมตร → กลับด้านวัดอะไรก็ได้
  ทางเลือกที่ทิ้ง: Hough detect เส้นกริดแล้วจับคู่ลำดับเส้นกับ id — พังง่ายเมื่อเส้นโดนบัง
  และต้องเขียนใหม่ทั้งหมด ส่วนวิธีหมุดใช้คำตอบที่มีอยู่แล้วเป็นตัวตั้ง
- **ประตูกันมั่ว 4 ชั้น (คืน None + เหตุผลไทย ไม่คืนตัวเลขมั่ว):** หมุด < 3 (2 ตัว fit ได้แต่
  residual = 0 เสมอ วัดคุณภาพไม่ได้เลย) · หมุดเรียงบนกริดเส้นเดียว (แกนไม่กระจาย) ·
  residual > 0.5 ม. (grid_ref บางตัวผิด) · px/m สองแกนต่างกัน > 5% (ภาพยืด/หมุน ไม่ใช่ orthographic)
- **สิ่งที่ได้ออกมา:** ทุก element ได้ `cv_measure.pos_m` (ตำแหน่งเมตรจริง) · element ที่โมเดล
  ไม่ได้ให้ ref ได้ `grid_ref_cv` (snap เข้าจุดตัดกริดที่ใกล้สุด ภายใน 0.5 ม. ไกลกว่านั้นไม่ยัดให้) ·
  element ที่โมเดลให้ ref มาแล้วได้ `grid_ref_check_m` (ห่างจากจุดนั้นจริงกี่เมตร = ตัวจับผิด
  ว่าโมเดลอ่าน ref ผิด) · จุดที่ CV เห็นแต่โมเดลไม่พูดถึงเลย (รวม self-harvest ของ pass2.5)
  ถูกรายงานพร้อม grid ref ที่คำนวณให้ — **แต่ไม่เติมเป็น element เอง ต้องให้คนตัดสิน**
- `parse_grid_ref()` พอร์ตจาก `raw-extraction-adapter.js` แบบตรงตัว (แถว = ตัวอักษร → y_lines,
  คอลัมน์ = ตัวเลข → x_lines) — สองฝั่งต้องอ่าน ref เดียวกันได้ความหมายเดียวกัน
- self-check ในไฟล์ (`python pass3_measure.py`): กริดสมมติ 50 px/m ต้อง fit ได้เป๊ะ, วัด A1→A2
  ได้ 4.00 ม., snap ถูกจุด, และต้อง**ปฏิเสธ**ทั้ง 3 เคสเสีย (หมุดน้อย/เรียงเส้นเดียว/เบี้ยว)
