**The most important bug of this stretch (commit `ad7bcb7`) — the server never starts**
```
while pgrep -f 'pip install' > /dev/null; do sleep 10; done && nohup ... serve_purson.py
```
This bash process has the string `pip install` in **its own** command line → `pgrep -f` finds itself every round → the condition is always true → the server never gets started

- Actually hit on machine 49411642: pip had finished by minute ~3 (log ends with `Successfully installed ... unsloth-2026.8.22`) but the waiter kept looping for another **~17 min** · GPU used **2 MiB**, not a single line of `purson.log` — **at a glance it looked like it was loading the 70GB model**, when nothing had started at all, and the money kept running
- Fixed to `pgrep -f '[p]ip install'` — the brackets make the regex pgrep uses not match the string that appears in that bash process's command line · proven with the real regex both ways before commit (old pattern finds itself / new pattern doesn't)
- **This is the same class as pkill killing its own ssh, which was hit 2 times today** — "a command that searches for a pattern on the command line and ends up finding itself" · it became the lesson of the day, hit as many as **3 times**
