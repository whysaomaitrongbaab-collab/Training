### บันทึกบทเรียน Voldemort ลง rule_of_tune (มะขามสั่ง) → **Lesson 16**

เพิ่ม `No_touch_box/docs/rule_of_tune.md` ข้อ 16 ครอบ 3 เรื่องที่คืนนี้สอน:
1. **ประตูทดสอบห้ามมีเฉลยอยู่ในตัวเอง** — v1 เขียน prompt ว่า "เช่น F1, B2, C1, ผ2" ซึ่ง F1/ผ2
   คือ GT ที่จะเอาไปเทียบ → โมเดลลอกกลับมา ได้คำตอบ**เหมือนกันเป๊ะ**ทั้งหน้าผังฐานรากและหน้ารูปตัด
   แต่สคริปต์นับว่า "ผ่าน 3/3" · อีกหน้า "ผ่าน" เพราะไล่เลข B1..B34 บังเอิญขึ้นต้นตรง GT
2. **ต้องมีตัวตรวจแยกแยะ** — บังคับให้คำตอบต่าง input ต้องต่างกัน (ตอบเหมือนกันข้าม input
   = ลายเซ็นของโมเดลที่ไม่ได้ดูภาพ) + ตัด degenerate output + ห้ามมีทางออก "อ่านไม่ออก"
   ตอนที่กำลังทดสอบว่า "มองเห็นไหม" + มีข้อง่ายคุมไว้ 1 ข้อ (อ่านตัวใหญ่สุด) เพื่อแยก
   "ตาบอด" ออกจาก "ความละเอียดไม่พอ"
3. **แก้ root cause ที่ยืนยันแล้ว 1 ตัว ≠ ปลดล็อกรอบนั้น** — t04 มี **2 โรคซ้อนกัน**
   Lesson 15 เจอแค่โรคแรก (`crop_to_patches`) ซึ่งแก้ถูกจริง (คืนนี้ยืนยันทั้งจาก source
   `mm_plugin.py:843` และจากการรันจริง 13 tile/3,482 token) **แต่ไม่พอ** เพราะโรคที่สอง
   (4-bit ทำ ViT ตาบอด) นอนอยู่ข้างใต้ และจะให้ผลหน้าตาเหมือนเดิมเป๊ะ: JSON สวย recall ~0%
   → กฎใหม่: หลังแก้ root cause แล้ว ให้ไล่ **รายการความเสี่ยงที่เหลือ** (ปกติเขียนไว้ใน
   design doc ของรอบนั้นอยู่แล้ว — กรณีนี้ dossier เขียนไว้ตั้งแต่ต้น) แล้วตั้งประตูดักทีละข้อ
