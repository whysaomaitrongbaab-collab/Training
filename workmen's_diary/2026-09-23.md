The difference is stdin — `ssh`/`scp` launched from `sh()` inherit the console's stdin and can block indefinitely, and because `sh()` uses `capture_output=True` the stderr that would have explained it is swallowed. That guard is load-bearing: `cmd_down` calls `sh(..., input="y\n")` for `vastai destroy`, and `subprocess.run` raises `ValueError` if both `input` and `stdin` are given. Verified afterwards by a real `presentation.py down` that destroyed an instance successfully.
- `ssh_base()` gained `BatchMode=yes` + `ConnectTimeout=15`. This is the same option set `ssh_alive()` already used — and `ssh_alive()` connected fine to the same host in the same minute the other path hung, which is what pointed at the difference. With `BatchMode` an auth problem fails immediately instead of raising an invisible password prompt.
- The `mkdir` retry loop and the `scp` call each got an explicit `timeout=` (60s / 5min) as a second net, so a future hang is loud and retried rather than silent. The `mkdir` loop catches `subprocess.TimeoutExpired` and continues to the next of its 6 attempts.
