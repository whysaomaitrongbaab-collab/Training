6. **Found and fixed why the live-read path has never produced `grid_refs`.** This had been raised earlier as "a known gap" without checking exactly why. Grepped `js/ai/prompts.js` directly: none of the four extraction passes (Pass 1 per-element detail, Pass 3 layout-ID survey, Pass 4 per-mark length-group counting) ever asked the model for a grid-line position — the JSON schema requested in each prompt simply never included that field. This is a prompt-design omission, not a model capability limit, and not the same issue as the raw-JSON import path (which already carries `grid_refs`/`grid_ref_start`/`grid_ref_end` because the Training team's own extraction schema defines them — separately verified working end to end by Ton on 2026-09-25, per `Constistant/docs/raw-json-gaps.md` §8).
   - **Fixed in `Constistant/js/ai/prompts.js`**: extended `qt_buildCountPrompt(elementId)` (Pass 3/4, the pass that already re-reads the layout/floor-plan page per element mark) to also ask for a `grid_refs` array per length-group, one entry per physical instance in reading order (left-to-right, top-to-bottom). Explicitly instructed the model to return **fewer entries than `qty` rather than guess** when some instances' positions aren't legible, flagging `grid_ref_partial`/`grid_ref_not_visible` instead.
   - **Fixed in `Constistant/js/drawing/drawing-index.js`**: the Pass 3/4 merge loop now accumulates `grid_refs` per length key across pages (parallel to the existing `qty` accumulator) and flattens them onto the final element as `el.grid_refs` before Pass 4's merge step.
   - **Fixed in `Constistant/js/drawing/drawing-bridge.js`**: `buildDrawingElement()` now threads `el.grid_refs` into the `DrawingElement` factory call for both the slab branch and the beam-like branch (defaulting to `[]`, never `null`/`undefined`).
   - **Important correctness check made along the way, not just assumed**: read `structure-model.js`'s `realGridTokensFor()` directly and found it requires `el.grid_refs.length === count` **exactly** — a partial match (e.g. the model only found 4 of 6 instances' positions) causes the *whole* element to fall back to the synthetic grid, not a partial real placement. This is existing, deliberate behavior (documented in that file's own comments — never mix real and synthetic positions within one element), so the new honest "send what you're sure of" prompt behavior is compatible with it, not fighting it: a partial live-read result will just be safely ignored rather than partially trusted. Caught and corrected a misleading code comment of my own that had implied `structure-model.js` "handles" partial `grid_refs` gracefully — it doesn't handle them, it discards them cleanly, which is a different and correct thing.
