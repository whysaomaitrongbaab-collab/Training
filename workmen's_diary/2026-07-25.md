### 5. Design: "split into 5 calls like Constistant but with primary_rawjson content" — trade-off analysis

Makham proposed: instead of a single call extracting the whole page, try splitting it multi-pass like the production pipeline. **The main trap:**
- This model was **trained on one call per page only** — the 28% measured = measured from a single call
- Splitting into sub-calls (survey ID / counting / etc.) = sub-tasks **the model never saw during training** → they'd be done by base Qwen, not the fine-tuned part = **implicitly giving up the advantage gained from tuning** (which is exactly what the existing Constistant pipeline already does, and calling the cloud is faster)
- **Time gets worse**: every call has to process the image again (~5,120 tokens ≈ 3 minutes per call on Makham's machine) → 5 calls/page = ~15 minutes/page spent just loading the image before generation
- **Conclusion**: to genuinely use the tuned model → one call per page (fix truncation with a right-sized ctx, accept it being slow); to genuinely go multi-pass → use the existing Constistant pipeline (cloud) **or** run a new training round with data formatted multi-pass to match how it's called (training has to match the way it's used)

### 6. Question: in real use on the web (with no Claude), how does it tell which page is which file type?

Looked at the real code — **the AI sorts it out itself**, there's a dedicated pass:
- **[drawing-index.js](../tune_ai/t01/data_before_tune) Pass 0/4**: render every page as a low-resolution thumbnail → send all pages together in 1 call with `QT_PROMPT_PAGE_IDENTIFY` → the AI answers `{"section_pages":[...],"layout_pages":[...]}`; if there are multiple layout pages, a modal pops up for a human to choose
- **wizard wz-step1.js**: loops page by page with `qt_classifySheetQwen(page)` → `{sheet_type, confidence}`, sorting into 5 types (floor_plan/section_detail/general_notes/schedule_table/unknown), shown as a badge under the thumbnail
- The point: page classification **is one of the 5 calls** (Pass 0), done with base Qwen (short prompt + thumbnail image); the web's taxonomy = 5 coarse types, different from primary_rawjson's 14 patterns
- **Important**: the tuned model **tags `pattern` per view inside its own answer** (PROMPT_SHORT instructs it to) → calling it as a single call **needs no separate Pass 0** (the Phase 10 test results already came out with `"pattern":"plan"/"section"` on their own)
