### 3. ตั้ง t02 — เทียบ Qwen3-VL กับ Qwen3.6 (มะขามสั่ง)

เหตุผลที่ห้าม rebuild: มี **7 ไฟล์ในบ้าน 05 ถูกแก้หลัง dataset ถูก build** (รวม `หน้า00_gridline.json`) → rebuild วันนี้จะได้คนละชุด แล้วผลต่างจะแยกไม่ออกว่ามาจากโมเดลหรือข้อมูล

**เจอบั๊ก 5 จุดใน `train_qwen3vl.py`** (ไฟล์เขียนตอน dataset ยัง 221 ตัวอย่าง และไม่เคยถูกรันจริง):

4. ไม่มี `enable_thinking=False` — บั๊กเดียวกับที่ทำให้ t01 วัดได้ 0/3

**ต่างกัน ~14 เท่า** — t01 เทรนด้วยภาพเบลอกว่ามาก แต่ยังชนะ t02 ทุกตัวชี้วัด แปลว่าที่วัดได้ทั้งวัน**ไม่ใช่การเทียบตระกูลโมเดลที่ยุติธรรม** ตอบได้แค่ "Qwen3.6 เห็นภาพหยาบยังชนะ" ไม่ใช่ "ตระกูล Qwen3.6 อ่านดีกว่า Qwen3-VL"

**เสนอมะขาม 2 ทาง: (A) หยุดรับผลพร้อมคำเตือน (B) เทรน t01 ใหม่ด้วย resize="max" เทียบให้ยุติธรรม (~$0.60-1.80 เพิ่ม) — มะขามเลือก A**

### 7. Phase 8 (export GGUF) — ล้มเหลวที่ sanity check, วินิจฉัยลึกจนถึงระดับ tensor ยืนยันว่าเป็นบั๊กเครื่องมือจริง

สั่ง export_gguf.py — โหลด base + adapter, merge สำเร็จไม่มี error, **แต่ sanity check จับได้ทันที**: output หลัง merge ไม่ตรง schema จริงเลย (`page_number/title/project` แทน `png/doc_page/discipline/sheet_code/views`) สคริปต์หยุดเองตามที่ออกแบบไว้ ไม่ไป quantize/อัปของเสีย

**⛔ พบว่าคำแนะนำเดิม ("adapter อัปก่อนเสมอ") ผิด** — อ่านโค้ดจริงพบว่า GGUF อัปก่อน adapter อัปสุดท้าย ถ้า sanity check ไม่ผ่านจะไม่มีอะไร backup เลยผ่านเส้นทาง Phase 8 — **backup ต้องแยกทำเองเสมอ ไม่พึ่ง Phase 8**

**วินิจฉัยลึกด้วยสคริปต์แยก 4 ตัว** (มะขามสั่ง "ทำต่อ...ให้ตายเราต้องได้ผลลัพท์" ให้ไล่หาสาเหตุจริง):
1. adapter ก่อน merge → output ตรง schema เป๊ะ 100% (adapter เองไม่มีปัญหา)
2. shape/orientation ของ delta_weight ที่ peft คำนวณ → **ถูกต้อง** ตรงกับ param.shape เป๊ะ
3. scaling factor → **ถูกต้อง** (2.0 = alpha/r)
4. ค่าจริงทั้ง tensor (201 ล้านค่า) ก่อน/หลัง merge → เปลี่ยนจริง 75.58% แต่**ขนาดเล็กผิดปกติ** (0.67% เทียบกับ behavior ที่พังสุดขั้ว)
5. เช็ค Unsloth's own `_merge_lora()` → **ไม่รองรับ MoE ParamWrapper เลย** จะแย่กว่าใช้ peft ตรงๆ ด้วยซ้ำ

**สรุป: บั๊กจริงในกลไก merge ของ peft/Unsloth สำหรับ LoRA แบบ target_parameters บน MoE experts** ไม่ใช่ปัญหาฝีมือเทรนหรือ dataset — adapter พิสูจน์แล้วว่าใช้งานได้จริง 100% แค่แปลงเป็น GGUF ไม่ได้ในตอนนี้

**มะขามตัดสินใจ 2026-07-28: หยุด** ไม่ไล่หา fix ต่อ (ทดลองไปแล้ว 3 สมมติฐานหลัก) — LoRA adapter backup แยกไว้แล้วก่อนหน้านี้ (ข้อ 6) นี่คือ "ผลลัพท์" ของรอบ t02 ที่มะขามต้องการ (ทูน Qwen3-VL เองสำเร็จ มีไฟล์พิสูจน์ได้)
