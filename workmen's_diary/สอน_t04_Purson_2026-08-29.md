Written per the order "I want to understand apply_arm.py and all file in t04_Purson, why they exist and what they're for"

## Understand 1 thing first — why almost everything in this folder is a "signpost"

t04 is an upgraded version of t03. For any gate that is **unchanged** from t03 (pass 0/1/2), we don't copy its files over;
instead we put a small README pointing back to the real file. Reason: if we copied them into 2 sets, one day someone would edit only one set
and the other set would go stale without anyone knowing (this really happened in this project; it's called "drift") — the real thing lives in only one place,
but there can be many signposts

## The whole conveyor belt, in 1 paragraph

1 house = a 20-30 page PDF → **pass 0** (the AI looks at one page at a time and answers what kind of drawing the page is) →
**pass 1** (code crops the images and sorts them into folders based on pass 0's answers) → **pass 1.5** (the CV eye, not AI —
it rubs example icons across the whole image to count how many columns/footings/beams there are and where they are) →
**pass 2/2.4** (the AI actually reads the drawing — 2.4 is the variant with a cheat sheet from CV stuck on the end of the prompt) →
**pass 2.5** (CV sweeps again using templates it just found on that very page, picking up the ones the central library missed) →
**pass 3** (the AI takes off dimensions/rebar from the confirmed list — the prompt is written, never run yet) →
into Constistant to compute the BOQ/BBS (pass 4, the secondary pages, was cancelled on 2026-08-29 — Makham ordered it himself:
"those pages aren't needed")

### pass0/README.md → points to tune_ai/t03/pass0_classify/

### pass1/README.md → points to tune_ai/t03/pass1_organize/organize.py
Pure code, no AI — it reads pass 0's results and actually crops the images (a page holding 2-3 images is cut apart into one file per image)

double the sharpness per area, for free

### pass1.5_cv/README.md → points to tools/cv_scan.py
The "CV eye" — not AI at all, so it can't make things up. It takes example icons from the library (tools/templates/) and rubs them across
the whole image, giving 3 files per page: coordinates JSON + a number-marked image + hint text
The number-marked image is now **for humans to look at only** (it was originally going to be fed to the model in arm 2.4b — cancelled)

### pass2/README.md → points to tune_ai/t03/pass2_used/ (7 prompts)
The prompts that actually read the drawing, one per subtask: gridline (builds the grid master) / plan (4 kinds of plan) /
section (sections with rebar specs) / schedule (summary schedules) / notes (project specifications) /
material_list (BOQ) / soil_boring_log (soil boring) — every one of them prepends _common.md

### pass2.4_hint/prompt.md
The "contract" for the hint block — it says what the cheat sheet stuck on the end of the prompt must contain (the point count per type +
the 4 anti-hallucination rules + the cv_mark instruction) and what it must not contain (**absolutely no dimension numbers** — sending them in
would mean teaching the model to break the "never guess dimensions from the image" rule with our own hands)
The code that actually builds the text is cv_hint_text() in tools/cv_scan.py — this file is only the contract,
to keep the two places from drifting apart
**2 experiment arms left:** arm 2 (no cheat sheet = the control) vs arm 2.4a (with a text cheat sheet)
Arm 2.4b (number-marked image): Makham ordered it cancelled on 2026-08-29, "just the hint is enough"

### pass2.4_hint/assembled_example.md

### pass2.5_harvest/README.md → points to tools/cv_scan.py (--pass25)

## apply_arm() — the experiment-arm switcher (it lives in infer_house_t03.py, not in a separate file)

There is no file named apply_arm.py — it is a **function**, `apply_arm()`, in
`tune_ai/t03/data_before_tune/infer_house_t03.py` (the script that runs the model evaluation)

**Why it exists:** the 2-arm experiment has to fire "the same page, the same prompt, the same model"
with the only difference being with/without the cheat sheet — if you leave it to a person to edit the prompt by hand every round, sooner or later they'll slip up and the results won't be comparable
apply_arm() is the middleman that takes the original content and "adds the extras" according to the arm chosen with the flag `--arm`,
so whoever runs it never has to touch the prompt at all

**How it works (after cutting 2.4b, what's left is very simple):**
1. Arm "2" → returns the original exactly, touches nothing (the control)
2. Arm "2.4a" → looks for the cheat-sheet file `<ชื่อรูป>_hint.txt` (ชื่อรูป = image name) in the sidecar folder (`--cv-dir`)
   Found → appends the cheat-sheet text to the end of the prompt and records `hint_used: true`
3. **Not found → returns the original + `hint_used: false`** — that row effectively becomes arm 2
   No error, no guessing, no empty cheat sheet created (important: for a house the template library doesn't know yet, CV will count 0,
   so there simply won't be a cheat sheet — the system doesn't break, it just records it so you can see)

**How to read the results:** every row in results has `hint_used` — for arm 2.4a, on pages that have a sidecar,
it must be true. If it's false, the `--cv-dir` path is wrong — stop and check before firing any more (otherwise you're burning GPU for nothing)

## Terms that come up often

- **sidecar** = by-product files placed next to the image (`_cv.json` / `_hint.txt` / `_marked.png`)
- **hint / cheat sheet** = text telling the model what CV saw and how many points of it — it's a clue, not the answer
  (the 4 rules keep the model from trusting the cheat sheet too much)
- **arm** = one experimental condition — arms are compared to answer "does the cheat sheet really help?"
- **GT (ground truth)** = the answer key a human has checked, used to score the model
- **recall_printed** = the percentage of the marks actually printed on the drawing that the model finds — the main metric
- **template / library** = the example icon images (tools/templates/) that CV rubs across the whole image to search
