### Phase 7: real measurement — much better than the previous round (after fixing the reasoning-mode bug)
- First run **JSON valid 0%** (worse than baseline!) — investigation found the model writes a long "thinking process" ahead of every answer (the Qwen3.6 model has a built-in reasoning mode), eating tokens so it never reaches the actual JSON
- **The real cause**: `apply_chat_template(add_generation_prompt=True)` didn't pass `enable_thinking=False` — no problem during training (which uses `add_generation_prompt=False` and never inserts a `<think>` tag), but at inference the default inserts an empty `<think>\n`, making the model keep writing long reasoning. Not a bug from training, just the inference template not matching the training one
- Fixed all 3 files `eval_fields.py`/`train_qwen36.py`/`export_gguf.py` to pass `enable_thinking=False` — re-ran and it passed immediately
- **Real results (`--limit 20`):** JSON valid 90% (unchanged), view exact match 70% (⬆️ from 60%), **element recall 28.2%** (⬆️⬆️⬆️ from 9.4% — 3x better), element_id/count exact 100%, element_type exact 87.5%. Weak point: 78 elements over-predicted (over-prediction)

### Phase 8: export GGUF + upload to HuggingFace — hit 5 real bugs back to back, fixed every one
1. The sanity check's `max_new_tokens=500` was too small → raised to 3000 → still failed (the test example is a table-of-contents page genuinely longer than 3000 tokens) → raised to 4096 → still failed (the model really does over-predict, it isn't truncation) → **fixed at the right spot**: changed the check from "does the full JSON parse successfully" to "does it start with the real JSON schema" (1200 tokens of generation is enough) + switched the test example to a shorter page
2. Unsloth auto-detects that this model is a VLM and tries to convert mmproj itself automatically (even though that was deliberately skipped) — it fails because the architecture is too new, which brings the whole export down with it. Tried fixing it by temporarily deleting `model.config.vision_config` — **that broke a different part instead** (tensor names nested 3 levels deep, `language_model.language_model.language_model...`) because it also affects how the main model is saved, not just mmproj — **the real fix**: monkey-patch `unsloth.save.convert_to_gguf` to pass `supported_vision_archs=set()` (forced, not just setting a default, because the kwarg is always present anyway), which triggers the fallback Unsloth already has built in (`is_vlm=False` + prints "Converting as text-only model") — doesn't affect the main model save at all
3. Disk full (`No space left on device`) from re-running many times without deleting the old artifacts — deleted old checkpoints duplicating the real LoRA adapter (33+11GB) + pip cache (3GB) + a stale old `outputs_qwen36/gguf/` (66GB), recovering 147GB
4. The script looked in the wrong path — Unsloth actually saves the GGUF files at `outputs_qwen36/gguf_gguf/` (duplicated suffix), not the plain `outputs_qwen36/gguf/` the script checks, so it reported "file not found" even though the conversion+quantization had genuinely succeeded — fixed the path without re-running merge/quantize (saving time), and wrote a separate `resume_upload.py` to upload straight from the files already present
