## 2.1 เซลล์หนึ่งตัว: ผลรวมถ่วงน้ำหนัก + ฟังก์ชันกระตุ้น

### 2.1.1 neuron คืออะไรในเชิงคณิตศาสตร์

neuron หนึ่งตัวรับตัวเลขหลายตัวเข้ามา คูณแต่ละตัวด้วยน้ำหนัก (weight) บวกกัน บวกค่าคงที่ (bias) แล้วส่งผ่านฟังก์ชันกระตุ้น (activation function) ตัวหนึ่ง

$$y = \sigma\left(\sum_{i} w_i x_i + b\right) = \sigma(\mathbf{w}\cdot\mathbf{x} + b)$$

- $x_i$ คือค่าที่ป้อนเข้า (เช่น ความกว้างคาน ความลึกคาน จำนวนเหล็กเสริม)
- $w_i$ คือน้ำหนักที่โมเดลจะเรียนรู้ บอกว่า input ตัวนั้นสำคัญแค่ไหน และไปทางบวกหรือลบ
- $b$ คือ bias เลื่อนผลรวมขึ้นลง เหมือนจุดตัดแกน y ของเส้นตรง
- $\sigma$ คือ activation function ที่ทำให้ผลลัพธ์ "ไม่เป็นเส้นตรง" (หัวข้อถัดไปจะอธิบายว่าทำไมต้องมี)

ส่วนในวงเล็บคือสมการเส้นตรงหลายตัวแปรที่วิศวกรคุ้นเคยดี ตัวอย่างเช่นสูตรน้ำหนักเหล็กเสริมต่อเมตร $0.00617 d^2$ ก็คือ "input ตัวเดียวคูณน้ำหนักตัวเดียว" neuron ต่างจากสูตรนี้แค่ตรงที่ค่า $w$ ไม่มีใครกำหนดให้ โมเดลหาเองจากข้อมูล

ตัวอย่างตัวเลข: input $\mathbf{x} = (1, 2)$, น้ำหนัก $\mathbf{w} = (0.5, -0.3)$, $b = 0.2$

$$z = 0.5(1) + (-0.3)(2) + 0.2 = 0.1$$

ถ้า $\sigma$ คือ ReLU (อธิบายด้านล่าง) ผลลัพธ์คือ $\max(0, 0.1) = 0.1$

### 2.1.2 ทำไมต้องมี activation ที่ไม่เป็นเส้นตรง

ลองคิดว่าถ้าไม่มี $\sigma$ เลย (หรือ $\sigma(z) = z$) แล้วเราต่อ neuron สองชั้น ชั้นแรกให้ $\mathbf{h} = W_1\mathbf{x}$ ชั้นสองให้ $y = W_2\mathbf{h} = W_2 W_1 \mathbf{x}$ แต่ $W_2 W_1$ ก็คือเมทริกซ์ตัวเดียว เรียกว่า $W$ ก็ได้ ดังนั้นโครงข่ายร้อยชั้นแบบเส้นตรงเท่ากับโครงข่ายชั้นเดียว มันวาดได้แค่ "ระนาบเรียบ" เท่านั้น ไม่มีทางวาดเส้นโค้งหรือรูปแบบซับซ้อนได้

เทียบกับงานโยธา: ถ้าเราสมมติว่ากำลังคอนกรีตเป็นฟังก์ชันเส้นตรงของอัตราส่วนน้ำต่อซีเมนต์ เราจะไม่มีวันจับพฤติกรรมช่วงที่มันอิ่มตัวได้ activation function คือสิ่งที่ให้โมเดล "หักงอ" ได้

### 2.1.3 activation ที่ใช้จริง 4 ตัว

| ชื่อ | สูตร | ใช้ที่ไหน | จุดสังเกต |
|---|---|---|---|
| sigmoid | $\sigma(z) = \frac{1}{1+e^{-z}}$ | ชั้นสุดท้ายของโจทย์ใช่/ไม่ใช่ | บีบค่าลง (0, 1) ความชันสูงสุดแค่ 0.25 |
| ReLU | $\max(0, z)$ | ชั้นซ่อนของ CNN/MLP ยุค 2012 เป็นต้นมา [4] | ถูกและง่าย แต่ถ้า $z<0$ gradient เป็น 0 (neuron "ตาย") |
| GELU | $z\,\Phi(z)$ โดย $\Phi$ คือ CDF ของแจกแจงปกติ [5] | ชั้นซ่อนใน Transformer เกือบทุกตัว (BERT, GPT, ViT) | เหมือน ReLU แต่โค้งมนแถวศูนย์ gradient ไม่ขาด |
| softmax | $\frac{e^{z_j}}{\sum_k e^{z_k}}$ | ชั้นสุดท้ายเมื่อต้องเลือก 1 จาก K ทาง | ผลรวมทุกช่องเป็น 1 ตีความเป็นความน่าจะเป็นได้ |

sigmoid กับ softmax ไม่ได้ทำหน้าที่ "หักงอ" เป็นหลัก แต่ทำหน้าที่แปลงตัวเลขดิบให้เป็นความน่าจะเป็น ส่วน ReLU และ GELU คือตัวที่ทำให้ชั้นซ่อนไม่เป็นเส้นตรง ตัวอย่างในงานเรา: ตอน pass0 ของ t03 ที่จำแนกว่าหน้านี้เป็นหน้าแบบคาน/เสา/ฐานราก/อื่น ๆ ชั้นสุดท้ายของโมเดลจำแนกใช้ softmax เพื่อให้ได้ความน่าจะเป็นของแต่ละหน้า

softmax ตัวอย่าง 3 ช่อง: $z = (2, 1, 0)$ ได้ $e^z = (7.39, 2.72, 1.00)$ ผลรวม 11.11 ดังนั้น softmax = (0.665, 0.245, 0.090) สังเกตว่าช่องที่ต่างกันแค่ 1 หน่วยกลายเป็นความน่าจะเป็นต่างกันเกือบ 3 เท่า เพราะ exponential ขยายความต่าง (บทที่ 5 จะใช้สมบัตินี้ใน attention และบทถัดไปจะโยงกับ temperature)

🎨 **ภาพที่จะวาดใน HTML:** ซ้ายเป็น neuron ตัวเดียวที่มี input 2 ช่อง ($x_1, x_2$) มีสไลเดอร์ปรับ $w_1, w_2, b$ ในช่วง -2 ถึง 2 ขวาเป็นกราฟ 2 มิติของ $x_1, x_2$ ที่ระบายสีตามค่าผลลัพธ์ (heatmap) เมื่อขยับ $w$ จะเห็น "เส้นแบ่ง" หมุน เมื่อขยับ $b$ จะเห็นเส้นเลื่อน มีปุ่มเลือก activation 4 แบบ (linear / sigmoid / ReLU / GELU) ให้เห็นว่า linear ให้แค่ระนาบเอียง ส่วน ReLU พับระนาบครึ่งหนึ่งให้เป็นศูนย์ และ GELU พับแบบโค้งมน แถบด้านล่างวาดกราฟ 1 มิติของ activation แต่ละตัวพร้อมอนุพันธ์ (เส้นประ) เพื่อให้เห็นว่า sigmoid มีอนุพันธ์สูงสุด 0.25 และ ReLU ฝั่งลบมีอนุพันธ์เป็น 0

```python
import numpy as np
from math import erf
x = np.array([1.0, 2.0]); w = np.array([0.5, -0.3]); b = 0.2
z = w @ x + b
relu = max(0.0, z)
gelu = 0.5 * z * (1 + erf(z / np.sqrt(2)))
sig  = 1 / (1 + np.exp(-z))
print(f"z={z:.3f} relu={relu:.3f} gelu={gelu:.4f} sigmoid={sig:.3f}")
logits = np.array([2.0, 1.0, 0.0])
print("softmax:", np.round(np.exp(logits) / np.exp(logits).sum(), 3))
```

## 2.2 ต่อเป็นชั้น: Multilayer Perceptron และ forward pass ด้วยเมทริกซ์

### 2.2.1 ชั้นหนึ่ง = การคูณเมทริกซ์หนึ่งครั้ง

ถ้ามี neuron หลายตัวในชั้นเดียวกัน แต่ละตัวมี $\mathbf{w}$ ของตัวเอง เราเรียงเวกเตอร์น้ำหนักเหล่านั้นเป็นแถวของเมทริกซ์ $W$ แล้วเขียนทั้งชั้นเป็นบรรทัดเดียว

$$\mathbf{h} = \sigma(W\mathbf{x} + \mathbf{b})$$

$W$ มีขนาด (จำนวน neuron ในชั้น × จำนวน input) แต่ละแถวคือ neuron หนึ่งตัว นี่คือเหตุผลที่ deep learning ทั้งวงการคือเรื่องของการคูณเมทริกซ์ (หัวข้อ 2.9 จะโยงเรื่องนี้กับ GPU)

โครงข่ายที่ต่อชั้นแบบนี้หลายชั้นเรียกว่า multilayer perceptron (MLP) หรือ feedforward network ใน Transformer ทุก block มี MLP แบบนี้ซ่อนอยู่ (บทที่ 5) และ LoRA ที่เราใช้ก็คือการเสริม "เมทริกซ์บาง ๆ" ข้าง $W$ พวกนี้ (บทที่ 6)

### 2.2.2 คำนวณ forward pass ให้ดู: โครงข่าย 2-2-1

ให้ input 2 ตัว ชั้นซ่อน 2 neuron (ReLU) และ output 1 ตัว (ไม่มี activation เพราะเป็นโจทย์ทำนายค่าต่อเนื่อง)

$$W_1 = \begin{pmatrix} 0.5 & -0.3 \\ 0.2 & 0.4 \end{pmatrix},\quad \mathbf{b}_1 = \begin{pmatrix} 0.2 \\ 0 \end{pmatrix},\quad W_2 = \begin{pmatrix} 0.7 & -0.5 \end{pmatrix},\quad b_2 = 0.2$$

input $\mathbf{x} = (1, 2)$ เป้าหมาย (target) $t = 0.5$

**ชั้นที่ 1**

$$\mathbf{z}_1 = W_1\mathbf{x} + \mathbf{b}_1 = \begin{pmatrix} 0.5(1) - 0.3(2) + 0.2 \\ 0.2(1) + 0.4(2) + 0 \end{pmatrix} = \begin{pmatrix} 0.1 \\ 1.0 \end{pmatrix}$$

$$\mathbf{h} = \text{ReLU}(\mathbf{z}_1) = \begin{pmatrix} 0.1 \\ 1.0 \end{pmatrix}$$

**ชั้นที่ 2**

$$y = W_2\mathbf{h} + b_2 = 0.7(0.1) - 0.5(1.0) + 0.2 = -0.23$$

**loss** ใช้ค่าคลาดเคลื่อนกำลังสอง (squared error) เหมือนตอนฟิตเส้นถดถอยในบทที่ 1

$$L = (y - t)^2 = (-0.23 - 0.5)^2 = 0.5329$$

จำเลขชุดนี้ไว้ หัวข้อ 2.4 จะไล่ย้อนกลับเพื่อหาว่าต้องแก้ $W_1, W_2$ อย่างไรให้ $L$ ลด

### 2.2.3 มิติของโมเดลจริง

ตัวอย่างข้างบนมีพารามิเตอร์ 4 + 2 + 2 + 1 = 9 ตัว โมเดล Qwen3-VL-8B ที่เราทูนมีราว 8 พันล้านตัว แต่โครงสร้างพื้นฐานเหมือนกันทุกประการ คือคูณเมทริกซ์ บวก bias ผ่าน activation แล้วส่งต่อ ต่างกันแค่ขนาดของ $W$ และวิธีเรียงชั้น (attention ในบทที่ 5 ก็สร้างจากการคูณเมทริกซ์แบบเดียวกัน)

🎨 **ภาพที่จะวาดใน HTML:** แผนภาพโครงข่าย 2-2-1 เป็นวงกลม 5 วงเชื่อมด้วยเส้น ค่าน้ำหนักเขียนกำกับบนเส้น (แก้ได้โดยคลิก) เมื่อกด "forward" จะมีแอนิเมชันตัวเลขไหลจากซ้ายไปขวา แสดงค่า $\mathbf{z}_1$, $\mathbf{h}$, $y$ ที่แต่ละวง และช่อง loss ด้านขวาสุด ด้านล่างมีมุมมอง "เมทริกซ์" ที่แสดง $W_1\mathbf{x}$ เป็นตารางคูณแถวต่อคอลัมน์ ไฮไลต์แถวและคอลัมน์ที่กำลังคูณให้เห็นว่า neuron หนึ่งตัว = แถวหนึ่งของ $W$ มีสไลเดอร์ "จำนวน neuron ในชั้นซ่อน" (2 → 8) ให้เห็นว่าเมทริกซ์ยืดออกแต่สูตรไม่เปลี่ยน

```python
import numpy as np
x = np.array([1.0, 2.0]); t = 0.5
W1 = np.array([[0.5, -0.3], [0.2, 0.4]]); b1 = np.array([0.2, 0.0])
W2 = np.array([0.7, -0.5]); b2 = 0.2
z1 = W1 @ x + b1
h  = np.maximum(z1, 0)
y  = W2 @ h + b2
print("z1 =", z1, " h =", h, " y =", round(y, 4), " loss =", round((y - t)**2, 4))
# คาดว่า: z1 = [0.1 1.0]  h = [0.1 1.0]  y = -0.23  loss = 0.5329
```

## 2.3 ทำไมต่อชั้นแล้ว "อะไรก็ได้": Universal Approximation

### 2.3.1 ทฤษฎีบทพูดว่าอะไร

Cybenko ปี 1989 [2] และ Hornik, Stinchcombe, White ปี 1989 [3] พิสูจน์แยกกันว่า โครงข่ายที่มีชั้นซ่อนเพียงชั้นเดียว แต่มี neuron มากพอ และใช้ activation ที่ไม่เป็นเส้นตรง (Cybenko ใช้ sigmoid, Hornik ขยายไปทุก "squashing function") สามารถประมาณฟังก์ชันต่อเนื่องใด ๆ บนช่วงปิดได้ใกล้เท่าที่ต้องการ

ภาษาคน: ไม่ว่าความสัมพันธ์ระหว่าง input กับ output จะซับซ้อนแค่ไหน ถ้ามันต่อเนื่อง จะมี MLP สักตัวที่วาดมันได้ ถามว่าเพราะอะไร ดูภาพนี้

- ReLU หนึ่งตัวคือ "เส้นตรงที่หักงอหนึ่งครั้ง"
- บวก ReLU สองตัวที่หักงอคนละจุด ได้เส้นหักงอสองครั้ง
- บวกไปเรื่อย ๆ ได้เส้นหักงอ N ครั้ง ซึ่งประมาณเส้นโค้งใด ๆ ได้ เหมือนที่วิศวกรประมาณเส้นโค้ง moment diagram ด้วยเส้นตรงต่อ ๆ กันหลายท่อน

### 2.3.2 สิ่งที่ทฤษฎีบท "ไม่ได้" พูด

นี่คือจุดที่คนเข้าใจผิดบ่อยที่สุด ทฤษฎีบทบอกว่า "มีอยู่" แต่ไม่ได้บอกว่า

1. ต้องใช้ neuron กี่ตัว (อาจต้องใช้จำนวนมหาศาลถ้าใช้ชั้นเดียว)
2. จะหาน้ำหนักชุดนั้นเจอด้วย gradient descent หรือไม่
3. จะได้น้ำหนักที่ทำงานกับข้อมูลที่ไม่เคยเห็น (generalize) หรือไม่

ข้อ 2 คือเรื่องของบทนี้ตั้งแต่หัวข้อ 2.4 ถึง 2.8 ข้อ 3 คือเรื่องของบทที่ 4 และเป็นเหตุผลที่ loss ต่ำในรอบ t02 ไม่รับประกัน recall สูง เหตุผลที่ในทางปฏิบัติเราใช้โครงข่าย "ลึก" หลายชั้นแทน "กว้าง" ชั้นเดียว คือฟังก์ชันหลายชนิดแทนได้ประหยัดกว่ามากเมื่อซ้อนชั้น (ชั้นบนใช้ผลของชั้นล่างซ้ำได้ เหมือนเราคำนวณ "แรงในคาน" ครั้งเดียวแล้วเอาไปใช้ออกแบบทั้งเหล็กบนและเหล็กล่าง)

🎨 **ภาพที่จะวาดใน HTML:** กราฟ 1 มิติ แสดงฟังก์ชันเป้าหมาย (เช่น เส้นโค้ง moment ของคานที่มีน้ำหนักแผ่และแรงกระทำเป็นจุด) เป็นเส้นสีเทา มีสไลเดอร์ "จำนวน ReLU" 1 → 30 เมื่อเพิ่มจะเห็นเส้นสีน้ำเงินที่เป็นผลรวมของ ReLU (ฟิตด้วย least squares ล่วงหน้า) ค่อย ๆ แนบเส้นเป้าหมาย พร้อมตัวเลข "ค่าคลาดเคลื่อนสูงสุด" ที่ลดลง ด้านล่างแสดง ReLU แต่ละตัวเป็นเส้นบาง ๆ สีต่างกันเพื่อให้เห็นว่าแต่ละตัวหักงอตรงไหน ปุ่ม "ชั้นเดียว 30 neuron" เทียบ "สองชั้น 6+6 neuron" ให้เห็นว่าสองชั้นได้คุณภาพใกล้เคียงกันด้วยพารามิเตอร์น้อยกว่า

## 2.4 Backpropagation: กฎลูกโซ่ที่ไล่ย้อนจากความผิดพลาด

### 2.4.1 ปัญหา: มีพารามิเตอร์เป็นล้าน จะรู้ได้ไงว่าแก้ตัวไหนเท่าไร

บทที่ 1 บอกว่า gradient descent คือ "ขยับพารามิเตอร์ไปทางที่ loss ลด" โดยดูจากอนุพันธ์ $\partial L/\partial w$ แต่ในโครงข่ายหลายชั้น $w$ ในชั้นแรกส่งผลถึง $L$ ผ่านชั้นซ่อนทั้งหมด จะหาอนุพันธ์ทีละตัวด้วยการลองขยับ (finite difference) ต้องรัน forward pass ซ้ำเท่าจำนวนพารามิเตอร์ ซึ่งสำหรับ 8 พันล้านตัวเป็นไปไม่ได้

Rumelhart, Hinton และ Williams ปี 1986 [1] ทำให้วิธีที่เร็วกว่านั้นแพร่หลาย นั่นคือ backpropagation ซึ่งก็คือกฎลูกโซ่ (chain rule) ของแคลคูลัสที่จัดลำดับการคำนวณให้ดี ใช้ forward 1 ครั้ง backward 1 ครั้ง ได้อนุพันธ์ของทุกพารามิเตอร์พร้อมกัน

### 2.4.2 กฎลูกโซ่

ถ้า $L$ ขึ้นกับ $y$ และ $y$ ขึ้นกับ $w$ แล้ว

$$\frac{\partial L}{\partial w} = \frac{\partial L}{\partial y}\cdot\frac{\partial y}{\partial w}$$

ในงานโยธาเราใช้สิ่งนี้ตลอด: ถ้าค่าก่อสร้างขึ้นกับปริมาณเหล็ก และปริมาณเหล็กขึ้นกับความลึกคาน "ค่าก่อสร้างเปลี่ยนเท่าไรเมื่อความลึกเปลี่ยน 1 ซม." ก็คือผลคูณของสองอัตรานั้น backprop คือการทำแบบนี้ย้อนจาก loss ไปทีละชั้น เก็บผลลัพธ์กลาง (เรียกว่า $\delta$) ไว้ใช้ต่อ จะได้ไม่คำนวณซ้ำ

### 2.4.3 คำนวณจริงกับโครงข่าย 2-2-1 จากหัวข้อ 2.2

จาก forward pass เรามี $\mathbf{x} = (1, 2)$, $\mathbf{z}_1 = \mathbf{h} = (0.1, 1.0)$, $y = -0.23$, $t = 0.5$, $L = 0.5329$

**ขั้น 1: อนุพันธ์ของ loss ต่อ output**

$$\frac{\partial L}{\partial y} = 2(y - t) = 2(-0.73) = -1.46$$

ค่าลบแปลว่า "ถ้า $y$ เพิ่ม loss จะลด" ซึ่งถูกต้องเพราะ $y$ ต่ำกว่าเป้า

**ขั้น 2: ชั้นที่ 2** ($y = W_2\mathbf{h} + b_2$)

$$\frac{\partial L}{\partial W_2} = \frac{\partial L}{\partial y}\,\mathbf{h}^\top = -1.46\times(0.1,\ 1.0) = (-0.146,\ -1.46)$$

$$\frac{\partial L}{\partial b_2} = -1.46$$

สังเกต: neuron ซ่อนตัวที่ 2 มีค่า $h = 1.0$ ใหญ่กว่าตัวแรก 10 เท่า น้ำหนักที่ต่อจากมันจึงได้ gradient ใหญ่กว่า 10 เท่า "ใครมีส่วนร่วมมาก ก็ถูกแก้มาก"

**ขั้น 3: ส่ง gradient ย้อนเข้าชั้นซ่อน**

$$\frac{\partial L}{\partial \mathbf{h}} = \frac{\partial L}{\partial y}\,W_2^\top = -1.46\times(0.7,\ -0.5) = (-1.022,\ 0.73)$$

**ขั้น 4: ผ่าน ReLU** อนุพันธ์ของ ReLU คือ 1 ถ้า $z > 0$ และ 0 ถ้า $z < 0$ ที่นี่ $\mathbf{z}_1 = (0.1, 1.0)$ เป็นบวกทั้งคู่ gradient จึงผ่านไปได้ทั้งหมด

$$\boldsymbol{\delta}_1 = \frac{\partial L}{\partial \mathbf{z}_1} = (-1.022,\ 0.73)$$

(ถ้า $z$ ตัวใดติดลบ ช่องนั้นจะเป็น 0 และน้ำหนักทั้งแถวของ neuron นั้นจะไม่ถูกแก้เลยในรอบนี้ นี่คือ "dead ReLU")

**ขั้น 5: ชั้นที่ 1** ($\mathbf{z}_1 = W_1\mathbf{x} + \mathbf{b}_1$)

$$\frac{\partial L}{\partial W_1} = \boldsymbol{\delta}_1\,\mathbf{x}^\top = \begin{pmatrix} -1.022 \\ 0.73 \end{pmatrix}(1,\ 2) = \begin{pmatrix} -1.022 & -2.044 \\ 0.73 & 1.46 \end{pmatrix},\qquad \frac{\partial L}{\partial \mathbf{b}_1} = \begin{pmatrix} -1.022 \\ 0.73 \end{pmatrix}$$

**ขั้น 6: อัปเดตด้วย SGD** learning rate $\eta = 0.1$ กฎคือ $w \leftarrow w - \eta\,\partial L/\partial w$

$$W_2 \leftarrow (0.7146,\ -0.354),\quad b_2 \leftarrow 0.346,\quad W_1 \leftarrow \begin{pmatrix} 0.6022 & -0.0956 \\ 0.127 & 0.254 \end{pmatrix},\quad \mathbf{b}_1 \leftarrow \begin{pmatrix} 0.3022 \\ -0.073 \end{pmatrix}$$

รัน forward อีกรอบด้วยน้ำหนักใหม่ได้ $y = 0.657$ และ $L = 0.0246$ ลดจาก 0.5329 ในขั้นเดียว แต่สังเกตว่า $y$ เลยเป้า 0.5 ไปแล้ว นี่คือสัญญาณว่า $\eta = 0.1$ ค่อนข้างใหญ่สำหรับโจทย์นี้ ถ้าใหญ่กว่านี้อีก loss จะเด้งไปมาแทนที่จะลู่เข้า (หัวข้อ 2.6 จะกลับมาเรื่องนี้)

🎨 **ภาพที่จะวาดใน HTML:** โครงข่าย 2-2-1 เดิม แต่ครั้งนี้กด "backward" แล้วมีลูกศรสีแดงไหลจากขวาไปซ้าย แสดงค่า $\partial L/\partial y$, $\partial L/\partial \mathbf{h}$, $\boldsymbol{\delta}_1$ ที่แต่ละวง และ gradient ของแต่ละเส้นน้ำหนักเขียนเป็นสีแดงใต้ค่าน้ำหนัก มีสไลเดอร์ learning rate (0.001 → 1.0) และปุ่ม "อัปเดต 1 ขั้น" ที่แสดงน้ำหนักใหม่กับ loss ใหม่ กราฟด้านล่างพล็อต loss ต่อจำนวนขั้น ให้ผู้เรียนเห็นว่า lr เล็กลู่เข้าช้า lr พอดีลู่เข้าเร็ว lr ใหญ่เกินเด้งหรือระเบิด ปุ่มพิเศษ "ทำให้ $z_1$ ติดลบ" (ตั้ง $b_1 = -0.5$) เพื่อดู dead ReLU ที่ gradient ทั้งแถวเป็นศูนย์

```python
import numpy as np
x = np.array([1.0, 2.0]); t = 0.5; lr = 0.1
W1 = np.array([[0.5, -0.3], [0.2, 0.4]]); b1 = np.array([0.2, 0.0])
W2 = np.array([0.7, -0.5]); b2 = 0.2
for step in range(3):
    z1 = W1 @ x + b1; h = np.maximum(z1, 0); y = W2 @ h + b2
    L = (y - t) ** 2
    dy  = 2 * (y - t)                 # dL/dy
    dW2 = dy * h;  db2 = dy           # ชั้น 2
    dh  = dy * W2                     # ส่งย้อนเข้าชั้นซ่อน
    dz1 = dh * (z1 > 0)               # ผ่าน ReLU
    dW1 = np.outer(dz1, x); db1 = dz1 # ชั้น 1
    print(f"step {step}: y={y:.4f} loss={L:.4f} dW2={np.round(dW2,3)}")
    W1 -= lr * dW1; b1 -= lr * db1; W2 -= lr * dW2; b2 -= lr * db2
# step 0: y=-0.2300 loss=0.5329   step 1: y=0.6567 loss=0.0246
```

## 2.5 Autograd: ให้ PyTorch ทำ backprop แทนเรา

### 2.5.1 กราฟการคำนวณ

PyTorch บันทึกทุกการดำเนินการที่ทำกับ tensor ที่ตั้ง `requires_grad=True` ไว้เป็นกราฟ (directed acyclic graph) ใบของกราฟคือ input และพารามิเตอร์ รากคือ loss เมื่อเรียก `.backward()` มันไล่กราฟจากรากกลับไปหาใบด้วยกฎลูกโซ่ให้เอง [25] นี่คือสิ่งที่หัวข้อ 2.4 ทำด้วยมือ

Karpathy เขียน micrograd [28] ซึ่งเป็น autograd engine ทั้งตัวในโค้ดราว 100 บรรทัด ถ้าอยากเห็นว่าข้างในไม่มีเวทมนตร์ แนะนำให้อ่านไฟล์ `engine.py` ของ repo นั้น และบทความ "Yes you should understand backprop" [27] อธิบายว่าทำไมแม้จะมี autograd แล้ว คนเทรนโมเดลก็ยังต้องรู้ว่า gradient ไหลผ่าน sigmoid หรือ ReLU อย่างไร (เพราะเวลาโมเดลไม่เรียน สาเหตุมักอยู่ตรงนั้น)

### 2.5.2 ตัวอย่าง 10 บรรทัด ที่ให้ผลตรงกับมือ

```python
import torch
x = torch.tensor([1.0, 2.0]); t = torch.tensor(0.5)
W1 = torch.tensor([[0.5, -0.3], [0.2, 0.4]], requires_grad=True)
b1 = torch.tensor([0.2, 0.0], requires_grad=True)
W2 = torch.tensor([0.7, -0.5], requires_grad=True)
b2 = torch.tensor(0.2, requires_grad=True)
y = W2 @ torch.relu(W1 @ x + b1) + b2      # forward
loss = (y - t) ** 2
loss.backward()                              # backward: เติม .grad ให้ทุกตัว
print(loss.item(), W2.grad, W1.grad)
# 0.5329  tensor([-0.146, -1.460])  tensor([[-1.022, -2.044], [0.730, 1.460]])
```

ค่าที่พิมพ์ออกมาตรงกับที่คำนวณด้วยมือในหัวข้อ 2.4 ทุกหลัก สิ่งที่ Unsloth/transformers/trl ทำตอนเราเทรน Qwen ก็คือโค้ดชุดนี้ในขนาดใหญ่: forward → loss → `backward()` → optimizer ปรับน้ำหนัก แค่ทำซ้ำหลายพันรอบ

ข้อควรระวังสองอย่างที่โยงกับบั๊กจริงของเรา: (1) `.grad` จะ "สะสม" ไม่ใช่เขียนทับ ต้องเรียก `optimizer.zero_grad()` ทุกรอบ เว้นแต่จงใจสะสมเพื่อทำ gradient accumulation (หัวข้อ 2.7) (2) ค่าที่ไม่ได้ตั้ง `requires_grad` จะไม่ถูกแก้เลย ซึ่งเป็นกลไกเดียวกับที่เรา "freeze vision tower" ใน t02 คือตั้งให้พารามิเตอร์ส่วนภาพไม่ต้องการ gradient แล้ว autograd จะข้ามไปโดยอัตโนมัติ

🎨 **ภาพที่จะวาดใน HTML:** กราฟการคำนวณเป็นโหนดกล่อง (x, W1, b1 → matmul → add → relu → matmul → add → sub → square → loss) วาดจากซ้ายไปขวา เมื่อกด "forward" ค่าตัวเลขปรากฏในแต่ละกล่อง เมื่อกด "backward" มีแถบสีแดงไหลจาก loss ย้อนกลับ และแต่ละกล่องแสดง local gradient ที่มันคูณเข้าไป (เช่น กล่อง square แสดง "×2(y-t)" กล่อง relu แสดง "×1 หรือ ×0") ปุ่มสลับ "requires_grad ของ W1" เปิด/ปิด เพื่อเห็นว่าเมื่อปิด แถบสีแดงหยุดที่ W1 (จำลอง freeze vision tower)

## 2.6 Optimizer: จาก SGD ถึง AdamW

### 2.6.1 SGD กับ learning rate

Stochastic Gradient Descent (SGD) คือกฎง่าย ๆ ในหัวข้อ 2.4

$$\theta_{t+1} = \theta_t - \eta\,\mathbf{g}_t$$

$\theta$ คือพารามิเตอร์ทั้งหมด $\mathbf{g}_t$ คือ gradient ณ ขั้น $t$ และ $\eta$ คือ learning rate คำว่า "stochastic" หมายถึงเราคำนวณ $\mathbf{g}$ จากตัวอย่างสุ่มชุดเล็ก (mini-batch) ไม่ใช่ทั้ง dataset ดังนั้น $\mathbf{g}$ มีสัญญาณรบกวน (noise) ทุกขั้น

ปัญหาของ SGD ล้วน ๆ: ถ้าพื้นผิว loss เป็นหุบเขาแคบยาว (แกนหนึ่งชันมาก อีกแกนราบมาก) $\eta$ ที่พอดีกับแกนชันจะเล็กเกินไปสำหรับแกนราบ โมเดลจะสั่นซ้ายขวาแต่เดินหน้าช้ามาก

### 2.6.2 Momentum: สะสมความเร็ว

Momentum เก็บ "ความเร็ว" $\mathbf{v}$ ที่เป็นค่าเฉลี่ยถ่วงน้ำหนักของ gradient ที่ผ่านมา

$$\mathbf{v}_{t} = \beta\,\mathbf{v}_{t-1} + \mathbf{g}_t,\qquad \theta_{t+1} = \theta_t - \eta\,\mathbf{v}_t$$

$\beta$ มักตั้ง 0.9 ผลคือทิศทางที่ gradient ชี้ตรงกันหลายขั้นจะสะสมจนเร็วขึ้น (ถ้า $\mathbf{g}$ คงที่ $\mathbf{v}$ จะลู่เข้า $\mathbf{g}/(1-\beta) = 10\mathbf{g}$) ส่วนทิศทางที่ gradient สลับบวกลบจะหักล้างกันเอง เหมือนลูกบอลกลิ้งลงหุบเขา ไม่ใช่คนเดินที่หยุดคิดใหม่ทุกก้าว Sutskever และคณะ 2013 [12] แสดงว่า momentum ที่ตั้งดีร่วมกับ initialization ที่ดี ทำให้เทรนโครงข่ายลึกได้โดยไม่ต้องใช้วิธี second-order ที่แพงกว่ามาก

### 2.6.3 Adam: learning rate ต่อพารามิเตอร์

Kingma และ Ba 2014 [13] เสนอ Adam ซึ่งเก็บสองอย่าง: ค่าเฉลี่ยของ gradient ($\mathbf{m}$, เหมือน momentum) และค่าเฉลี่ยของ gradient กำลังสอง ($\mathbf{v}$)

$$\mathbf{m}_t = \beta_1\mathbf{m}_{t-1} + (1-\beta_1)\mathbf{g}_t,\qquad \mathbf{v}_t = \beta_2\mathbf{v}_{t-1} + (1-\beta_2)\mathbf{g}_t^2$$

$$\hat{\mathbf{m}}_t = \frac{\mathbf{m}_t}{1-\beta_1^t},\qquad \hat{\mathbf{v}}_t = \frac{\mathbf{v}_t}{1-\beta_2^t},\qquad \theta_{t+1} = \theta_t - \eta\,\frac{\hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t}+\epsilon}$$

ค่ามาตรฐาน $\beta_1 = 0.9$, $\beta_2 = 0.999$, $\epsilon = 10^{-8}$ ส่วน $\hat{\mathbf{m}}, \hat{\mathbf{v}}$ คือการแก้ความเอนเอียง (bias correction) เพราะขั้นแรก ๆ $\mathbf{m}, \mathbf{v}$ เริ่มจากศูนย์จึงเล็กเกินจริง

ตัวอย่างขั้นแรก ($t=1$) กับ gradient $g = 0.5$: $m_1 = 0.05$, $v_1 = 0.00025$ แก้ bias ได้ $\hat{m}_1 = 0.5$, $\hat{v}_1 = 0.25$ ดังนั้นขนาดก้าวคือ $\eta\times 0.5/\sqrt{0.25} = \eta\times 1$ ลองใหม่กับ $g = 0.005$ ก็ได้ $\eta\times 1$ เหมือนกัน นี่คือหัวใจของ Adam: **ขนาดก้าวไม่ขึ้นกับขนาดของ gradient** พารามิเตอร์ที่ gradient เล็กจิ๋ว (เช่น ชั้นลึก ๆ หรือ embedding ของ token หายาก) ก็ยังได้ก้าวประมาณ $\eta$ เท่ากับตัวอื่น

นี่คือเหตุผลที่ `lr=1e-4` ของ t02 ตีความได้ตรง ๆ ว่า "แต่ละพารามิเตอร์ของ LoRA ขยับประมาณ 0.0001 ต่อขั้น (ในช่วง lr สูงสุด)" โดยไม่ต้องรู้ว่า gradient ของมันใหญ่แค่ไหน ถ้าเป็น SGD จะตีความแบบนี้ไม่ได้

### 2.6.4 AdamW: weight decay ที่แยกออกมา

Weight decay คือการดึงน้ำหนักทุกตัวเข้าหาศูนย์นิด ๆ ทุกขั้น ($\theta \leftarrow \theta - \eta\lambda\theta$) เพื่อไม่ให้น้ำหนักโตจนโมเดลจำข้อมูลเทรน (เป็น regularization ชนิดหนึ่ง หัวข้อ 2.8) Loshchilov และ Hutter 2017 [14] ชี้ว่าเมื่อเอา weight decay ไปใส่ใน gradient แบบเดิม (L2 regularization) แล้วผ่านตัวหารของ Adam มันจะถูกปรับสเกลจนไม่ทำหน้าที่ตามที่ตั้งใจ จึงเสนอ AdamW ที่ "แยก" (decouple) weight decay ออกมาบวกตรง ๆ กับพารามิเตอร์หลังขั้น Adam AdamW เป็น optimizer มาตรฐานของการเทรน Transformer และเป็นค่าเริ่มต้นใน Trainer ของ HuggingFace ที่ Unsloth ใช้

🎨 **ภาพที่จะวาดใน HTML:** พื้นผิว loss 2 มิติรูปหุบเขายาวเอียง (contour plot) มีจุดเริ่มต้นเดียวกัน ปุ่มเลือก optimizer (SGD / SGD+momentum / Adam / AdamW) และสไลเดอร์ learning rate กด "เล่น" แล้วเห็นเส้นทางของแต่ละ optimizer วิ่งพร้อมกันเป็นคนละสี: SGD ซิกแซกในหุบเขา momentum ซิกแซกน้อยลงและเดินหน้าเร็วกว่า Adam เดินตรงไปตามก้นหุบเขาเพราะปรับสเกลแต่ละแกน ตัวนับ "จำนวนขั้นถึงเป้า" ของแต่ละตัว ส่วนแผงขวาแสดงตัวเลข $\mathbf{m}$, $\mathbf{v}$, $\hat{\mathbf{m}}/\sqrt{\hat{\mathbf{v}}}$ ของ Adam แบบเรียลไทม์ให้เห็นว่าขนาดก้าวอยู่แถว $\eta$ เสมอ

```python
import numpy as np
# เทียบ SGD กับ Adam บนพารามิเตอร์ตัวเดียว: gradient เล็ก g=0.005 ตลอด
eta, b1, b2, eps = 0.01, 0.9, 0.999, 1e-8
w_sgd = w_adam = 1.0; m = v = 0.0
for t in range(1, 101):
    g = 0.005
    w_sgd -= eta * g
    m = b1*m + (1-b1)*g;  v = b2*v + (1-b2)*g*g
    w_adam -= eta * (m/(1-b1**t)) / (np.sqrt(v/(1-b2**t)) + eps)
print(f"หลัง 100 ขั้น  SGD ขยับ {1-w_sgd:.4f}   Adam ขยับ {1-w_adam:.4f}")
# SGD ขยับ 0.005 (=100×0.01×0.005)  Adam ขยับ ~1.0 (=100×0.01×1)
```

## 2.7 Batch, step, epoch และ learning rate schedule

### 2.7.1 mini-batch และ gradient accumulation

ทุกขั้น (step) เราคำนวณ gradient จากตัวอย่างชุดหนึ่งเรียกว่า batch ยิ่ง batch ใหญ่ gradient ยิ่งใกล้ค่าเฉลี่ยจริงของทั้ง dataset (noise น้อย) แต่กิน VRAM มากขึ้นตามสัดส่วนเพราะต้องเก็บ activation ของทุกตัวอย่างไว้ทำ backward

ใน t02 ตัวอย่างหนึ่งคือภาพ + JSON ยาว 10k-13k token บน GPU เช่าตัวเดียว ใส่ได้แค่ 1 ตัวอย่างต่อครั้ง (`batch 1`) แต่ gradient จากตัวอย่างเดียวมี noise สูงมาก ทางออกคือ gradient accumulation: ทำ forward+backward 8 ครั้ง ปล่อยให้ `.grad` สะสม (จำจากหัวข้อ 2.5 ว่ามันสะสมโดยธรรมชาติ) แล้วค่อยให้ optimizer ก้าว 1 ครั้ง ผลเทียบเท่ากับ batch 8 ในแง่คณิตศาสตร์ของ gradient (ต่างกันตรง batch norm ซึ่ง Transformer ไม่ใช้) [26]

$$\text{effective batch} = \text{batch} \times \text{grad\_accum} = 1 \times 8 = 8$$

ต้นทุนคือเวลา: 8 forward/backward ต่อ 1 ก้าว ไม่ได้ประหยัดเวลาเลย ประหยัดแค่ VRAM

### 2.7.2 step กับ epoch

- 1 **epoch** = โมเดลเห็นทุกตัวอย่างใน dataset ครบ 1 รอบ
- 1 **step** (optimizer step) = อัปเดตน้ำหนัก 1 ครั้ง

ถ้า dataset มี $N$ ตัวอย่าง จำนวน step ต่อ epoch คือ $N / \text{effective batch}$ ตัวอย่าง: t05 ใช้ประมาณ 1,000 ตัวอย่างต่อ fold ถ้าเทรนด้วย effective batch 8 จะได้ 125 step ต่อ epoch และ 3 epoch = 375 step นี่คือ "จำนวนก้าว" ทั้งหมดที่โมเดลได้ปรับตัว ซึ่งน้อยมากเมื่อเทียบกับการ pretrain (หลักล้าน step) และเป็นเหตุผลว่าทำไม fine-tuning จึงอ่อนไหวกับ learning rate มาก

### 2.7.3 Learning rate schedule: warmup แล้ว cosine

learning rate ไม่ได้คงที่ตลอดการเทรน t02 ใช้ cosine schedule ซึ่งมาจาก Loshchilov และ Hutter 2016 [15] ร่วมกับ warmup ช่วงสั้น ๆ ตอนต้น (Goyal และคณะ 2017 [16] แสดงว่า warmup ช่วยให้การเทรนช่วงแรกที่น้ำหนักยังสุ่มไม่พังเมื่อใช้ batch ใหญ่)

$$\eta(s) = \begin{cases} \eta_{\max}\dfrac{s}{S_w} & s < S_w \\[8pt] \eta_{\max}\cdot\dfrac{1}{2}\left(1+\cos\left(\pi\dfrac{s - S_w}{S - S_w}\right)\right) & s \ge S_w \end{cases}$$

$s$ คือ step ปัจจุบัน $S$ คือ step ทั้งหมด $S_w$ คือจำนวน step ของ warmup ตัวอย่างกับ $\eta_{\max} = 10^{-4}$, $S = 375$, $S_w = 20$:

| step | 0 | 10 | 20 | 100 | 200 | 300 | 375 |
|---|---|---|---|---|---|---|---|
| lr | 0 | 5.0e-5 | 1.0e-4 | 8.8e-5 | 4.9e-5 | 1.1e-5 | 0 |

เหตุผลเชิงสัญชาตญาณ: ช่วงแรกก้าวยาวเพื่อเดินเข้าใกล้หุบเขาเร็ว ๆ ช่วงท้ายก้าวสั้นลงเรื่อย ๆ เพื่อ "จอด" ที่ก้นหุบเขาโดยไม่กระเด้ง เหมือนการขันน็อต ตอนแรกหมุนเร็ว ตอนใกล้แน่นค่อย ๆ ขัน

🎨 **ภาพที่จะวาดใน HTML:** กราฟ lr ต่อ step มีสไลเดอร์ "จำนวนตัวอย่าง N" (200-3,000), "batch", "grad_accum", "epoch", "warmup ratio" และ "lr สูงสุด" เมื่อขยับจะเห็นตัวเลข effective batch, step ต่อ epoch, step รวม เปลี่ยนตาม และเส้น cosine ยืดหด ปุ่ม preset "t02: batch 1 × accum 8 × 3 epoch, lr 1e-4" ด้านล่างมีแอนิเมชัน "ถัง gradient" ที่เติมทีละ 1/8 ต่อ forward/backward และเทออก (optimizer step) เมื่อเต็ม พร้อมแถบ VRAM ที่ไม่โตเมื่อเพิ่ม accum แต่โตเมื่อเพิ่ม batch

```python
import numpy as np
N, batch, accum, epochs, warm_ratio, lr_max = 1000, 1, 8, 3, 0.05, 1e-4
S = (N // (batch * accum)) * epochs; Sw = int(S * warm_ratio)
def lr(s):
    if s < Sw: return lr_max * s / Sw
    return lr_max * 0.5 * (1 + np.cos(np.pi * (s - Sw) / (S - Sw)))
print("effective batch", batch*accum, "| steps/epoch", N//(batch*accum), "| total steps", S)
for s in [0, Sw, S//4, S//2, 3*S//4, S]: print(f"step {s:4d}  lr {lr(s):.2e}")
```

## 2.8 อ่าน loss curve และ regularization

### 2.8.1 loss ที่เราเห็นคืออะไร

ตอนทูน Qwen loss ที่วิ่งบนหน้าจอคือ cross-entropy เฉลี่ยต่อ token ของ JSON คำตอบ: ค่า $-\log p$ ที่โมเดลให้กับ token ที่ถูกต้อง loss 0.3 หมายถึงโดยเฉลี่ยโมเดลให้ความน่าจะเป็น $e^{-0.3} \approx 0.74$ กับ token ถัดไปที่ถูก loss 1.8 คือ $e^{-1.8} \approx 0.17$ (บทที่ 5 จะอธิบายที่มาของ cross-entropy อย่างละเอียด)

### 2.8.2 train loss กับ validation loss

train loss วัดบนตัวอย่างที่โมเดล "เห็นและถูกแก้ด้วย" val loss วัดบนตัวอย่างที่กันไว้ไม่ให้แตะ สัญญาณที่ต้องดู

- ทั้งคู่ลง = กำลังเรียนรู้จริง
- train ลงต่อ แต่ val หยุดแล้วเริ่มขึ้น = **overfit** โมเดลเริ่มจำตัวอย่างเทรนแทนที่จะเรียนกฎ เหมือนนักศึกษาที่ท่องข้อสอบเก่าจนตอบข้อสอบใหม่ไม่ได้
- ทั้งคู่ไม่ลง = underfit หรือ lr/ข้อมูลมีปัญหา
- train loss กระโดดขึ้นฉับพลัน (loss spike) = lr สูงเกินไป หรือตัวอย่างผิดปกติ

จุดสำคัญที่ตอบคำถามเปิดของบท: loss ต่ำบน train ไม่ได้บอกอะไรเกี่ยวกับหน้าแบบใหม่ และแม้ val loss จะดี **val loss วัดคนละอย่างกับ element recall** โมเดลอาจทำนาย token ส่วนใหญ่ถูก (วงเล็บ เครื่องหมาย ชื่อฟิลด์) แต่ผิดตรงเลขคานสองสามตัวที่สำคัญที่สุด บทที่ 4 จะขยายว่าทำไมต้องวัดด้วย metric ของงานจริง ไม่ใช่ loss

### 2.8.3 Dropout

Srivastava และคณะ 2014 [18] เสนอให้ "ปิด" neuron แบบสุ่มด้วยความน่าจะเป็น $p$ ในทุก forward pass ระหว่างเทรน (ตอนใช้งานจริงเปิดหมดแล้วสเกลชดเชย) ผลคือ neuron ตัวไหนพึ่งพาเพื่อนบ้านตัวใดตัวหนึ่งมากเกินไปไม่ได้ ต้องเรียนรู้ feature ที่แข็งแรงด้วยตัวเอง เหมือนการออกแบบโครงสร้างให้มี redundancy คือถ้าคานตัวใดเสียหาย โครงสร้างต้องยังยืนอยู่

ค่า `lora_dropout=0.05` ที่ Unsloth แนะนำ (และหลาย config ของเราใช้) หมายถึงปิด 5% ของ input ที่เข้าสู่ adapter ของ LoRA แบบสุ่มระหว่างเทรน เป็นค่าที่เบามาก เพราะ LoRA มีพารามิเตอร์น้อยอยู่แล้วจึง overfit ยากกว่า full fine-tuning Raschka [30] รายงานจากการทดลองว่า dropout ของ LoRA ให้ผลต่างกันไม่มาก และปัจจัยที่สำคัญกว่าคือ rank กับการใส่ LoRA ครบทุกชั้น

### 2.8.4 Weight decay

อธิบายไปแล้วในหัวข้อ 2.6.4 กลไกคือดึงน้ำหนักเข้าหาศูนย์ ป้องกันไม่ให้พารามิเตอร์ตัวใดตัวหนึ่งโตเพื่อจำตัวอย่างเฉพาะ ค่ามาตรฐานใน AdamW คือ 0.01 หรือ 0.1 สำหรับการทูน LoRA มักตั้งเล็กหรือศูนย์ เพราะ adapter เริ่มจากศูนย์อยู่แล้ว (บทที่ 6)

🎨 **ภาพที่จะวาดใน HTML:** กราฟ loss ต่อ epoch สองเส้น (train สีน้ำเงิน, val สีส้ม) จำลองจากโจทย์ฟิตพหุนามกับข้อมูลที่มี noise สไลเดอร์ "ขนาดโมเดล" (degree 1-15), "dropout p" (0-0.5), "weight decay" (0-0.1) และ "จำนวนตัวอย่างเทรน" (10-200) เมื่อโมเดลใหญ่และข้อมูลน้อยจะเห็นเส้น val แยกออกจาก train และโค้งขึ้น (จุด overfit ถูกทำเครื่องหมายด้วยเส้นประ) เมื่อเพิ่ม dropout/weight decay ช่องว่างจะแคบลง แผงขวาแสดงกราฟฟังก์ชันที่ฟิตได้ทับจุดข้อมูล ให้เห็นว่า overfit หน้าตาเป็นเส้นที่คดเคี้ยวผ่านทุกจุด และมีกล่องข้อความเตือน "val loss ต่ำสุด ≠ recall สูงสุด" พร้อมแถบ recall จำลองที่แกว่งไม่ตรงกับ val loss

```python
import numpy as np
rng = np.random.default_rng(0)
x = rng.uniform(-1, 1, 12); y = np.sin(3*x) + 0.2*rng.normal(size=12)   # ข้อมูลเทรน 12 จุด
xv = rng.uniform(-1, 1, 200); yv = np.sin(3*xv) + 0.2*rng.normal(size=200)  # validation
for deg in [1, 3, 5, 9, 11]:
    for lam in [0.0, 1e-3]:                     # lam = weight decay แบบ ridge
        A = np.vander(x, deg+1); Av = np.vander(xv, deg+1)
        w = np.linalg.solve(A.T@A + lam*np.eye(deg+1), A.T@y)
        tr = np.mean((A@w - y)**2); va = np.mean((Av@w - yv)**2)
        print(f"degree {deg:2d} decay {lam:.0e}  train {tr:.3f}  val {va:.3f}")
# degree สูง + decay 0: train ต่ำมาก แต่ val พุ่ง = overfit; decay ช่วยดึง val ลง
```

## 2.9 ทำไมโครงข่ายลึกเทรนยาก: initialization, vanishing/exploding gradient

### 2.9.1 gradient คือผลคูณยาว ๆ

จากหัวข้อ 2.4 gradient ของชั้นแรกคือผลคูณของ "local gradient" ของทุกชั้นที่อยู่ถัดไป ถ้ามี $L$ ชั้น และแต่ละชั้นคูณด้วยตัวประกอบประมาณ $a$ gradient ที่มาถึงชั้นแรกจะประมาณ $a^L$

- $a < 1$: gradient หดจนเป็นศูนย์ (vanishing) ชั้นแรก ๆ ไม่ได้เรียนอะไรเลย ตัวอย่าง: sigmoid มีอนุพันธ์สูงสุด 0.25 ผ่าน 10 ชั้นเหลืออย่างมาก $0.25^{10} \approx 10^{-6}$
- $a > 1$: gradient โตจนระเบิด (exploding) น้ำหนักกระโดดไปค่ามหาศาล loss กลายเป็น NaN

Pascanu, Mikolov และ Bengio 2013 [8] วิเคราะห์ปัญหานี้อย่างเป็นระบบใน RNN (ซึ่งเป็นกรณีสุดโต่งเพราะใช้ $W$ ตัวเดิมซ้ำทุกขั้น) และเสนอ gradient clipping คือถ้า norm ของ gradient เกินค่าที่ตั้ง ให้ย่อลงมาเท่าค่านั้น ค่า `max_grad_norm=1.0` ที่เป็นค่าเริ่มต้นใน Trainer ของ HuggingFace คือสิ่งนี้ และเป็นตัวอย่างของ "ค่าที่ไม่ได้ตั้งแต่กำหนดชะตา" (บั๊กข้อ 5 ในรายการของเรา) ที่ควรรู้ว่ามีอยู่

### 2.9.2 Initialization: เริ่มให้ $a \approx 1$

ถ้าน้ำหนักเริ่มต้นสุ่มใหญ่ไป สัญญาณจะระเบิดตั้งแต่ forward pass ถ้าเล็กไปจะหดจนหาย Glorot และ Bengio 2010 [6] เสนอให้สุ่มน้ำหนักด้วยความแปรปรวน $2/(n_{in}+n_{out})$ (Xavier initialization) เพื่อรักษาความแปรปรวนของสัญญาณให้คงที่ข้ามชั้นสำหรับ activation แบบ tanh/sigmoid He และคณะ 2015 [7] ปรับเป็น $2/n_{in}$ สำหรับ ReLU (Kaiming initialization) เพราะ ReLU ตัดครึ่งหนึ่งของสัญญาณทิ้ง จึงต้องเริ่มใหญ่ขึ้นเป็นสองเท่าเพื่อชดเชย

LoRA ใช้หลักการเดียวกันแต่พลิกมุม: เมทริกซ์ $B$ เริ่มที่ศูนย์ทั้งหมด เพื่อให้ตอนเริ่มเทรน adapter ไม่รบกวนโมเดลเดิมเลย (บทที่ 6)

### 2.9.3 สองสิ่งที่แก้ปัญหานี้จริงในโมเดลสมัยใหม่

initialization ที่ดีช่วยได้แค่ตอนเริ่ม พอเทรนไปน้ำหนักเปลี่ยน สมดุลก็เสีย สิ่งที่ทำให้เทรนโครงข่ายร้อยชั้นได้จริงคือสองกลไกในหัวข้อถัดไป

🎨 **ภาพที่จะวาดใน HTML:** โครงข่ายชั้นซ่อน 1 neuron ต่อกัน $L$ ชั้น (สไลเดอร์ $L$ = 1-50) แต่ละชั้นแสดงเป็นกล่อง เมื่อเลือก activation (sigmoid/tanh/ReLU) และวิธี init (สุ่มใหญ่ / สุ่มเล็ก / Xavier / Kaiming) จะแสดงแถบสองแถวคือ "ขนาดสัญญาณ forward" และ "ขนาด gradient backward" ต่อชั้นในสเกล log เห็นได้ทันทีว่า sigmoid + 20 ชั้น gradient ตกไป $10^{-12}$ ส่วน ReLU + Kaiming อยู่แถว 1 ตลอด ปุ่ม "เปิด gradient clipping" ที่ตัดยอดแถบ backward ไม่ให้เกิน 1

## 2.10 Residual connection และ Layer Norm: ปูทางไป Transformer

### 2.10.1 Residual: ให้ชั้นเรียน "ส่วนต่าง" แทน "ทั้งหมด"

He และคณะ 2015 [9] (ResNet) เปลี่ยนสมการชั้นจาก $\mathbf{h}_{l+1} = f(\mathbf{h}_l)$ เป็น

$$\mathbf{h}_{l+1} = \mathbf{h}_l + f(\mathbf{h}_l)$$

ชั้นไม่ต้องสร้าง output ทั้งหมดขึ้นใหม่ แค่เรียนว่าจะ "เพิ่มอะไร" เข้ากับสิ่งที่ผ่านมา ผลข้างเคียงที่สำคัญกว่าอยู่ตอน backward: อนุพันธ์ของ $\mathbf{h}_{l+1}$ ต่อ $\mathbf{h}_l$ คือ $1 + f'(\mathbf{h}_l)$ มี "1" อยู่เสมอ gradient จึงมีทางด่วนไหลตรงจาก loss กลับไปชั้นแรกโดยไม่ถูกคูณด้วย $a^L$ ปัญหา vanishing gradient จึงหายไปเป็นส่วนใหญ่ นี่คือเหตุผลที่ ResNet เทรนได้ 152 ชั้นทั้งที่ก่อนหน้านั้น 20 ชั้นก็ยากแล้ว

เทียบกับงานโยธา: การเสริมกำลังคานเดิมด้วยแผ่นเหล็กบาง (เรียนแค่ส่วนต่างที่ต้องเพิ่ม) แทนการหล่อคานใหม่ทั้งตัว (เรียนทุกอย่างจากศูนย์) แนวคิดเดียวกันนี้กลับมาอีกครั้งใน LoRA: $W + \Delta W$ (บทที่ 6)

ทุก block ของ Transformer มี residual connection สองเส้น (รอบ attention และรอบ MLP) เมื่อบทที่ 5 พูดถึง "residual stream" ให้นึกถึงสมการนี้

### 2.10.2 Layer Norm: ตั้งสเกลใหม่ทุกชั้น

Ioffe และ Szegedy 2015 [10] เสนอ batch normalization ที่ปรับสัญญาณแต่ละ feature ให้มีค่าเฉลี่ย 0 ความแปรปรวน 1 โดยคำนวณสถิติข้าม batch วิธีนี้พึ่ง batch ใหญ่ ซึ่งใช้กับ batch 1 อย่างของเราไม่ได้ Ba, Kiros และ Hinton 2016 [11] เสนอ layer normalization ที่คำนวณสถิติข้าม feature ของตัวอย่างเดียวแทน

$$\text{LN}(\mathbf{h}) = \gamma\odot\frac{\mathbf{h} - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta,\qquad \mu = \frac{1}{d}\sum_i h_i,\quad \sigma^2 = \frac{1}{d}\sum_i (h_i - \mu)^2$$

$\gamma, \beta$ คือพารามิเตอร์เรียนรู้ได้ที่ให้โมเดลเลือกสเกลและจุดศูนย์ใหม่ได้ถ้าต้องการ ตัวอย่างมิติ 3: $\mathbf{h} = (2, 4, 6)$ ได้ $\mu = 4$, $\sigma^2 = 8/3$, $\sigma \approx 1.63$ ผลลัพธ์ก่อนคูณ $\gamma$ คือ $(-1.22, 0, 1.22)$ ไม่ว่า $\mathbf{h}$ จะเป็น $(20, 40, 60)$ หรือ $(0.2, 0.4, 0.6)$ ก็ได้ผลเดียวกัน layer norm จึงทำให้ขนาดสัญญาณไม่โตหรือหดสะสมข้ามชั้น

LLM ปัจจุบันส่วนใหญ่รวมถึงตระกูล Qwen ใช้ RMSNorm ของ Zhang และ Sennrich 2019 [39] ซึ่งตัดการลบ $\mu$ ออก เหลือแค่หารด้วย root mean square ประหยัดการคำนวณโดยผลไม่ต่างกันมาก และวางไว้ "ก่อน" attention/MLP ในแต่ละ block (Pre-LN) ซึ่ง Xiong และคณะ 2020 [38] แสดงว่าทำให้ gradient ตอนเริ่มเทรนสงบกว่า Post-LN แบบเดิม จนแทบไม่ต้องพึ่ง warmup

🎨 **ภาพที่จะวาดใน HTML:** ซ้ายเปรียบเทียบสองโครงข่าย 30 ชั้นเรียงแนวตั้ง แบบ plain กับแบบ residual (มีเส้นโค้งข้ามชั้น) กด "backward" แล้วเห็นความเข้มของ gradient ในแต่ละชั้น: plain จางหายไปตั้งแต่ชั้นที่ 10 ส่วน residual เข้มถึงชั้นแรกเพราะมี "ทางด่วน" ขวาเป็นแผงตัวเลข layer norm: ช่องกรอกเวกเตอร์ 4 มิติ แสดง $\mu$, $\sigma$ และผลลัพธ์ พร้อมสไลเดอร์ "คูณสเกล input × 0.01 ถึง × 100" ที่เห็นว่าผลลัพธ์หลัง LN ไม่เปลี่ยน สลับ LayerNorm/RMSNorm ได้ ด้านล่างเป็นแผนภาพ Transformer block (Pre-LN) ที่ไฮไลต์ residual สองเส้นและ norm สองจุด เพื่อส่งต่อไปบทที่ 5

```python
import torch, torch.nn as nn
torch.manual_seed(0)
def deep(x, L, residual):
    for _ in range(L):
        f = torch.tanh(x @ torch.randn(64, 64) * 0.2)
        x = x + f if residual else f
    return x
for res in [False, True]:
    x = torch.randn(1, 64, requires_grad=True)
    deep(x, 30, res).sum().backward()
    print("residual" if res else "plain   ", "grad norm ที่ input =", f"{x.grad.norm():.2e}")
# plain: ค่าเล็กมาก (vanishing)  residual: ค่าอยู่ในระดับปกติ
```

## 2.11 ทำไมต้อง GPU และ precision ของตัวเลข

### 2.11.1 ทุกอย่างคือการคูณเมทริกซ์

การคูณเมทริกซ์ $(n\times n)(n\times n)$ ใช้ $2n^3$ การดำเนินการจุดลอยตัว (FLOPs: $n^3$ ครั้งคูณ + $n^3$ ครั้งบวก) แต่ละช่องของผลลัพธ์คำนวณได้อิสระจากช่องอื่น ดังนั้นถ้ามีหน่วยประมวลผลหมื่นตัว ก็คำนวณหมื่นช่องพร้อมกันได้ นี่คือสิ่งที่ GPU ถูกออกแบบมาทำ (เดิมเพื่อคำนวณพิกเซลบนจอ ซึ่งก็อิสระต่อกันเหมือนกัน) ขณะที่ CPU มีคอร์ไม่กี่สิบตัวที่เก่งเรื่องงานตามลำดับ

ตัวเลขให้เห็นภาพ: A100 มี FP32 ประมาณ 19.5 TFLOPS แต่ Tensor Core ที่ทำงานกับ bf16 ได้ 312 TFLOPS [41] ต่างกัน 16 เท่า และตัวเลขหลังนี้ใช้ได้เฉพาะเมื่องานเป็นการคูณเมทริกซ์ในความละเอียดต่ำ นี่คือเหตุผลที่ "precision" กับ "ความเร็ว" เป็นเรื่องเดียวกัน

ประมาณต้นทุนการเทรนคร่าว ๆ: Kaplan และคณะ 2020 [42] ใช้กฎ compute $\approx 6 \times$ (จำนวนพารามิเตอร์) $\times$ (จำนวน token) สำหรับ forward + backward (forward ราว 2 FLOPs ต่อพารามิเตอร์ต่อ token และ backward อีกราว 2 เท่าของ forward) สำหรับตัวอย่าง t02 ที่ 12k token กับโมเดล 8B: $6\times 8\times10^9\times 1.2\times10^4 \approx 5.8\times10^{14}$ FLOPs ต่อตัวอย่าง ถ้า GPU ทำได้จริง 100 TFLOPS ก็ราว 6 วินาทีต่อตัวอย่าง (LoRA ลด backward ส่วนน้ำหนักลง แต่ activation gradient ยังต้องคำนวณเต็ม จึงไม่ได้เร็วขึ้นเป็นเท่าตัวอย่างที่หลายคนคิด)

### 2.11.2 fp32 / fp16 / bf16 / int4

ตัวเลขจุดลอยตัวเก็บเป็น 3 ส่วน: เครื่องหมาย 1 บิต, เลขชี้กำลัง (exponent) กำหนด "ช่วง" ที่แทนได้, และ mantissa กำหนด "ความละเอียด"

| รูปแบบ | บิต | exponent | mantissa | ช่วงโดยประมาณ | ใช้ที่ไหน |
|---|---|---|---|---|---|
| fp32 | 32 | 8 | 23 | $\pm 3.4\times10^{38}$ | มาตรฐาน, master weights, optimizer state |
| fp16 | 16 | 5 | 10 | $\pm 65{,}504$ | GPU รุ่นเก่า, ต้องใช้ loss scaling [21] |
| bf16 | 16 | 8 | 7 | เท่า fp32 | เทรน LLM ปัจจุบัน (Ampere ขึ้นไป) [22] |
| int4 | 4 | - | - | 16 ระดับ | น้ำหนักของโมเดลฐานใน QLoRA (NF4) [20], GGUF Q4 ตอน deploy |

fp16 มีปัญหาที่ช่วงแคบ: gradient ที่เล็กกว่า $6\times10^{-8}$ กลายเป็นศูนย์ และ activation ที่เกิน 65,504 กลายเป็น inf Micikevicius และคณะ 2017 [21] แก้ด้วยการเก็บ master weight เป็น fp32 และคูณ loss ด้วยค่าคงที่ (loss scaling) ก่อน backward เพื่อดัน gradient ให้พ้นช่วง underflow bf16 (Google ออกแบบสำหรับ TPU [22]) แก้ที่ต้นเหตุด้วยการให้ exponent 8 บิตเท่า fp32 แลกกับ mantissa ที่หยาบกว่า (ทศนิยมราว 2-3 หลัก) ซึ่ง Google รายงานว่าโครงข่ายประสาทไวต่อช่วงมากกว่าความละเอียด bf16 จึงเป็นค่ามาตรฐานของ Unsloth บน GPU ที่รองรับ และเป็นสิ่งที่เราใช้ใน t02

int4 คือการเก็บน้ำหนักด้วย 16 ระดับ ต้องมี "สเกล" ต่อบล็อกเพื่อแปลงกลับ QLoRA ของ Dettmers และคณะ 2023 [20] เสนอ NF4 ที่วางระดับทั้ง 16 ให้เหมาะกับการแจกแจงปกติของน้ำหนัก และแสดงว่าทูน LoRA บนโมเดลฐานที่บีบเป็น 4 บิตได้ผลใกล้เคียง 16 บิต โดยใช้ VRAM ลดลงมาก (ทูนโมเดล 65B บน GPU 48 GB ตัวเดียว) นี่คือ "QLoRA 4-bit" ใน config ของ t02 ส่วนความเสี่ยงของการ quantize ตอน deploy (บั๊กข้อ 3 ของเรา: Q4_K_M ทำให้ผลเปลี่ยนโดยไม่ได้วัดซ้ำ) จะว่ากันในบทเรื่อง quantization

### 2.11.3 Gradient checkpointing: แลกเวลากับ VRAM

จากหัวข้อ 2.4 backward ต้องใช้ค่า activation ($\mathbf{h}$, $\mathbf{z}$) ของทุกชั้นที่เก็บไว้ตอน forward สำหรับตัวอย่างยาว 12k token มิติ 4096 activation หนึ่ง tensor ใน bf16 คือ $12{,}000\times 4{,}096\times 2$ byte $\approx 98$ MB และแต่ละ block เก็บหลาย tensor คูณจำนวน block หลายสิบชั้น รวมกันเป็นสิบ GB ซึ่งมากกว่าน้ำหนักโมเดลที่บีบ 4 บิตเสียอีก นี่คือสาเหตุหลักของ OOM ในงานเรา (บั๊กข้อ 7) ไม่ใช่ตัวน้ำหนัก

Chen และคณะ 2016 [23] เสนอ gradient checkpointing: เก็บ activation ไว้แค่บางชั้น (checkpoint) แล้วตอน backward คำนวณ forward ซ้ำเฉพาะช่วงระหว่าง checkpoint ผลคือหน่วยความจำลดเหลือ $O(\sqrt{n})$ สำหรับโครงข่าย $n$ ชั้น แลกกับการทำ forward เพิ่มอีกราวหนึ่งรอบ

`use_gradient_checkpointing="unsloth"` ใน config ของเราคือรุ่นที่ Unsloth ปรับปรุง [24] โดยย้าย activation ที่ checkpoint ไว้ไปพักบน RAM ของ CPU แทน VRAM ทำให้ลดหน่วยความจำได้อีกราว 30% เมื่อเทียบกับ checkpointing มาตรฐาน โดยช้าลงราว 2% ตามที่ Unsloth รายงาน และเป็นเหตุผลที่เราใส่ตัวอย่างยาว 10k-13k token ลง GPU ตัวเดียวได้

🎨 **ภาพที่จะวาดใน HTML:** สามแผง (1) แถบ VRAM ที่แบ่งเป็นส่วน "น้ำหนัก" "optimizer state" "activation" มีสไลเดอร์ความยาว token (1k-16k), batch, precision ของน้ำหนัก (fp32/bf16/int4) และสวิตช์ gradient checkpointing (ปิด / มาตรฐาน / unsloth) เห็นว่าส่วน activation โตเป็นเส้นตรงตาม token และหดฮวบเมื่อเปิด checkpointing โดยมีนาฬิกา "เวลาต่อ step" เพิ่มขึ้นเล็กน้อย (2) ตัวเลขจุดลอยตัวแบบโต้ตอบ: กรอกค่าเช่น 0.1234567 แล้วเห็นบิตของ fp32/fp16/bf16 และค่าที่ปัดจริง พร้อมกรอก 70000 เพื่อเห็น fp16 กลายเป็น inf (3) ตาราง 16 ระดับของ int4/NF4 บนแกนจำนวนจริง ลากสไลเดอร์ "ค่าน้ำหนักจริง" แล้วเห็นว่ามันถูกปัดไปที่ระดับไหน และค่าคลาดเคลื่อน

```python
import torch
w = torch.tensor([0.1234567, 70000.0, 3e-8])
for dt in [torch.float32, torch.float16, torch.bfloat16]:
    print(dt, w.to(dt).tolist())
# fp16: 70000 -> inf, 3e-8 -> 0 (underflow)   bf16: ช่วงพอ แต่ 0.1234567 -> 0.123535 (หยาบ)
# นับ VRAM ของ activation หนึ่ง tensor: token × d × 2 byte (bf16)
tokens, d = 12_000, 4096
print(f"activation 1 tensor = {tokens*d*2/1e6:.0f} MB")
```

- **บั๊กข้อ 5 (ค่า default พลิกผล):** `max_grad_norm`, `weight_decay`, `warmup_ratio`, `adam_beta2` ล้วนมีค่าเริ่มต้นใน Trainer และทุกตัวอยู่ในสมการของบทนี้ การ "ไม่ตั้ง" ไม่ได้แปลว่าไม่มี
- **บั๊กข้อ 7 (OOM):** หัวข้อ 2.11.3 บอกว่า activation ของตัวอย่างยาวคือตัวกิน VRAM หลัก ไม่ใช่น้ำหนัก 35B ของ MoE ที่บีบแล้ว การลด `max_length`, เปิด checkpointing หรือลด batch จึงช่วยมากกว่าการหาโมเดลเล็กลง
- **บั๊กข้อ 2 (adapter ไม่ถูก merge):** จากหัวข้อ 2.10.1 LoRA คือ $W + \Delta W$ ถ้าตอน export เอาเฉพาะ $W$ ไปโดยไม่บวก $\Delta W$ โมเดลที่ได้คือโมเดลฐานเป๊ะ ๆ และไม่มี error ใด ๆ บอก เพราะในเชิงคณิตศาสตร์มันก็ยังเป็นโครงข่ายที่ทำงานได้ปกติ

**loss ต่ำแต่ recall ต่ำ (คำถามเปิด):** หัวข้อ 2.8.2 ตอบว่า loss วัดความน่าจะเป็นเฉลี่ยต่อ token ส่วน recall วัดว่าคานทุกตัวถูกพบหรือไม่ token ส่วนใหญ่ของ JSON เป็นโครงสร้างที่เดาง่าย โมเดลได้ loss ต่ำจากส่วนนั้น ขณะที่ token ไม่กี่ตัวที่บอกว่ามีคาน B7 อยู่หรือไม่ ผิดได้โดย loss แทบไม่ขยับ นี่คือเหตุผลที่โปรเจกต์ใช้ element recall และ leave-one-out เป็นตัววัดจริง ไม่ใช่ loss

**CV2 คู่กับโครงข่ายประสาท:** `cv2.matchTemplate` ใน tools/pattern_recognition.py คือการคูณและบวกแบบ sliding window ซึ่งในทางคณิตศาสตร์เป็น cross-correlation แบบเดียวกับชั้น convolution ที่บทที่ 3 จะอธิบาย ต่างกันตรงที่ template ของเราถูกกำหนดโดยคน ส่วน filter ของ CNN ถูกเรียนรู้ด้วย backprop ของบทนี้

## 2.13 ระดับนักวิจัย: คำถามที่ยังเปิดอยู่

1. **ทำไม Adam ชนะ SGD บน Transformer และมีอะไรดีกว่า Adam ไหม** Zhang และคณะ 2024 [31] วิเคราะห์ Hessian ของ Transformer แล้วพบว่า block ต่าง ๆ (embedding, attention, MLP) มีสเปกตรัมของ Hessian ต่างกันมาก (block heterogeneity) SGD ที่ใช้ lr เดียวทั้งโมเดลจึงแพ้ Adam ที่ปรับสเกลรายพารามิเตอร์ ฝั่ง optimizer ใหม่ Muon ของ Jordan และคณะ 2024 [32] ใช้การ orthogonalize เมทริกซ์ update ของชั้นซ่อน (ส่วน embedding และ head ยังใช้ AdamW) Liu และคณะ 2025 [33] รายงานประสิทธิภาพ compute ราว 2 เท่าของ AdamW ที่ scale ใหญ่ และ Kimi K2 (2025) [34] ใช้ MuonClip เทรนโมเดล 1T พารามิเตอร์บน 15.5T token โดยไม่มี loss spike นี่คือ state of the art ที่เปลี่ยนเร็ว ส่วนหลักการ (momentum, per-parameter scaling, decoupled weight decay) ยังเป็นพื้นฐานที่ไม่เปลี่ยน

2. **ทำไมโมเดลที่จำข้อมูลเทรนได้หมดถึงยัง generalize** Zhang และคณะ 2017 [35] แสดงว่า CNN มาตรฐานฟิต label ที่สุ่มมั่ว ๆ ได้ 100% แปลว่า "ความจุ" ของโมเดลไม่ได้อธิบายว่าทำไมมันถึง generalize เมื่อ label ถูก Nakkiran และคณะ 2019 [36] พบ double descent: เมื่อโมเดลใหญ่ขึ้นเรื่อย ๆ val error ลง แล้วขึ้น แล้วลงอีก ขัดกับกราฟ U ในตำราสถิติ และ Power และคณะ 2022 [37] พบ grokking: โมเดลที่ overfit ไปนานแล้วอยู่ ๆ ก็ generalize ได้เมื่อเทรนต่อไปอีกมาก ทั้งสามเรื่องยังไม่มีทฤษฎีเดียวอธิบายครบ และมีผลตรงกับเราคือ "val loss เริ่มขึ้น = ควรหยุด" อาจไม่จริงเสมอไป

3. **batch เล็กหรือใหญ่ดีกว่ากัน** Keskar และคณะ 2016 [17] เสนอว่า batch ใหญ่ลู่เข้าสู่ minima ที่ "แหลม" ซึ่ง generalize แย่กว่า minima "ราบ" ที่ batch เล็กพร้อม noise หาเจอ ขณะที่ Goyal และคณะ 2017 [16] แสดงว่าถ้าปรับ lr ตามสัดส่วน (linear scaling rule) และใช้ warmup ก็ใช้ batch 8,192 ได้โดยไม่เสียความแม่น ข้อถกเถียงนี้ยังไม่จบ สำหรับเรา effective batch 8 อยู่ในโซน "เล็กมาก" ซึ่ง noise สูง ข้อดีคืออาจหา minima ราบ ข้อเสียคือ lr ที่เหมาะสมแคบ

4. **Pre-LN, RMSNorm, และ activation แบบ gated** สถาปัตยกรรม MLP ใน LLM ปัจจุบันไม่ใช่ ReLU/GELU ธรรมดา แต่เป็น SwiGLU ของ Shazeer 2020 [40] ที่ใช้สองเมทริกซ์คูณกันแบบมี gate ซึ่งเขายอมรับใน paper ว่าไม่มีคำอธิบายเชิงทฤษฎีว่าทำไมดีกว่า ทำนองเดียวกัน Pre-LN [38] และ RMSNorm [39] ได้รับความนิยมจากผลเชิงประจักษ์มากกว่าทฤษฎี ในระดับนักวิจัย คำถาม "normalization ควรอยู่ตรงไหนและจำเป็นแค่ไหน" ยังเปิดอยู่

5. **precision ต่ำได้แค่ไหนก่อนพัง** QLoRA [20] แสดงว่าน้ำหนักฐาน 4 บิตพอสำหรับการทูน แต่คำถามที่ยังเถียงกันคือ activation และ gradient ลดได้แค่ไหน (fp8 กำลังเป็นมาตรฐานของ GPU รุ่นใหม่) และการ quantize หลังทูน (post-training quantization อย่าง Q4_K_M ของ llama.cpp) ทำลายความรู้ที่ adapter เพิ่มเข้ามามากน้อยเพียงใด ซึ่งเป็นสิ่งที่บั๊กข้อ 3 ของเราชนเข้าเต็ม ๆ และควรถูกวัดทุกครั้ง ไม่ใช่สมมติ

## 2.14 แบบฝึกหัด

**ข้อ 1 (คำนวณ):** ใช้โครงข่าย 2-2-1 ในหัวข้อ 2.2 แต่เปลี่ยน $\mathbf{b}_1 = (-0.5, 0)$ คำนวณ forward pass และ gradient $\partial L/\partial W_1$ แถวแรก อธิบายว่าเกิดอะไรขึ้นและทำไม

<details><summary>เฉลย</summary>

$z_{1,1} = 0.5 - 0.6 - 0.5 = -0.6 < 0$ ดังนั้น $h_1 = 0$ และอนุพันธ์ของ ReLU ที่ช่องนี้เป็น 0 gradient แถวแรกของ $W_1$ เป็น $(0, 0)$ neuron ตัวนี้ "ตาย" ในรอบนี้ ไม่ว่า loss จะใหญ่แค่ไหนก็ไม่ถูกแก้ ถ้าเป็นแบบนี้ทุกตัวอย่าง มันจะตายถาวร นี่คือเหตุผลหนึ่งที่ Transformer ใช้ GELU/SwiGLU ที่ gradient ไม่เป็นศูนย์สนิทฝั่งลบ
</details>

**ข้อ 2 (คิด):** เพื่อนบอกว่า "เปลี่ยน batch 1 accum 8 เป็น batch 8 accum 1 จะได้ผลเหมือนกันแต่เร็วกว่า" ถูกไหม มีเงื่อนไขอะไร

<details><summary>เฉลย</summary>

ในแง่ gradient ที่ optimizer เห็น เท่ากันโดยประมาณ (ผลรวมของ gradient จาก 8 ตัวอย่างเดียวกัน ยกเว้นความต่างเล็กน้อยจากการปัดเศษและวิธีหาร loss) และ batch 8 เร็วกว่าจริงเพราะ GPU คูณเมทริกซ์ใหญ่ครั้งเดียวได้ประสิทธิภาพกว่า แต่เงื่อนไขคือ VRAM ต้องพอเก็บ activation ของ 8 ตัวอย่างพร้อมกัน ซึ่งกับตัวอย่าง 12k token บน GPU เช่าตัวเดียว ไม่พอ นั่นคือเหตุผลเดียวที่เราใช้ accumulation
</details>

**ข้อ 3 (คำนวณ):** ใช้ schedule ในหัวข้อ 2.7.3 กับ $S = 375$, $S_w = 20$, $\eta_{\max} = 10^{-4}$ ที่ step 250 lr เท่าไร ถ้า dataset โตเป็น 2,000 ตัวอย่างโดย config อื่นเท่าเดิม step รวมและ lr ที่ step 250 เปลี่ยนเป็นเท่าไร

<details><summary>เฉลย</summary>

$S = 375$: $\eta(250) = 10^{-4}\times 0.5(1+\cos(\pi\cdot 230/355)) \approx 10^{-4}\times 0.5(1 - 0.545) \approx 2.3\times10^{-5}$

$N = 2{,}000$: step ต่อ epoch = 250, $S = 750$, $S_w = 20$ (ถ้าตั้งเป็นจำนวนคงที่) $\eta(250) = 10^{-4}\times 0.5(1+\cos(\pi\cdot 230/730)) \approx 10^{-4}\times 0.5(1+0.543) \approx 7.7\times10^{-5}$ ข้อสังเกต: dataset ใหญ่ขึ้น 2 เท่า ทำให้ lr ที่ step เดียวกันสูงขึ้น 3 เท่า เพราะ schedule ยืดตาม $S$ ค่า lr จึงไม่ใช่ "ค่าที่ตั้ง" ตัวเดียว แต่เป็นฟังก์ชันของขนาด dataset ด้วย
</details>

**ข้อ 4 (รันโค้ด):** แก้โค้ดในหัวข้อ 2.10.2 ให้ทดลอง $L = 5, 10, 30, 100$ และเปลี่ยนตัวคูณ 0.2 เป็น 0.05 และ 1.0 บันทึก grad norm ของ plain กับ residual ทำตารางแล้วสรุปว่าเมื่อไร plain พัง เมื่อไร residual พัง

<details><summary>เฉลย</summary>

plain: grad norm หดเป็นเลขชี้กำลังตาม $L$ เมื่อสเกลเล็ก (0.05) และระเบิดเมื่อสเกลใหญ่ (1.0) ตั้งแต่ $L$ ไม่กี่สิบ residual: ทนได้ที่สเกล 0.05-0.2 ถึง $L = 100$ แต่ที่สเกล 1.0 ก็ยังโตได้เพราะ $1 + f'$ มากกว่า 1 ทุกชั้น (นี่คือเหตุผลที่ residual ต้องมาพร้อม layer norm และ init เล็ก)
</details>

**ข้อ 5 (คิด):** ตัวอย่างหนึ่งของเรามี 12k token โมเดล d = 4096 มี 36 block สมมติแต่ละ block ต้องเก็บ activation เทียบเท่า 10 tensor ขนาด (token × d) ใน bf16 คำนวณ VRAM สำหรับ activation ทั้งหมด แล้วเทียบกับน้ำหนัก 8B พารามิเตอร์ที่เก็บเป็น NF4 (4 บิตต่อตัว ไม่นับสเกล)

<details><summary>เฉลย</summary>

activation: $12{,}000\times4{,}096\times2\text{ byte}\times10\times36 \approx 35.4$ GB น้ำหนัก NF4: $8\times10^9\times0.5$ byte $= 4$ GB activation ใหญ่กว่าน้ำหนักเกือบ 9 เท่า นี่คือเหตุผลที่ gradient checkpointing (เก็บแค่ input ของแต่ละ block แล้วคำนวณซ้ำ) ลด VRAM ได้มหาศาล และการลด `max_length` มีผลมากกว่าการเปลี่ยนโมเดลให้เล็กลง (ตัวเลข 36 block และ 10 tensor เป็นสมมติฐานเพื่อฝึกคำนวณ ค่าจริงต้องดูจาก config ของโมเดล)
</details>

## สรุปบทนี้ใน 5 บรรทัด

1. neuron = ผลรวมถ่วงน้ำหนัก + activation ที่ไม่เป็นเส้นตรง ชั้นหนึ่ง = การคูณเมทริกซ์ และการต่อชั้นทำให้ประมาณฟังก์ชันต่อเนื่องใด ๆ ได้ (universal approximation) แต่ทฤษฎีบทไม่รับประกันว่าจะหาน้ำหนักเจอหรือจะ generalize
2. backpropagation คือกฎลูกโซ่ที่ไล่ย้อนจาก loss ทีละชั้น autograd ของ PyTorch ทำสิ่งนี้ให้ และ `requires_grad=False` คือกลไกของการ freeze
3. AdamW ให้ก้าวขนาดราว lr ต่อพารามิเตอร์โดยไม่ขึ้นกับขนาด gradient, gradient accumulation ทำให้ batch 1 × 8 = effective batch 8, cosine schedule ไล่ lr ลงตามจำนวน step ซึ่งขึ้นกับขนาด dataset
4. loss ต่ำไม่เท่ากับ recall สูง ต้องดู val loss และ metric ของงานจริง dropout กับ weight decay คือเครื่องมือกันจำข้อสอบเก่า
5. โครงข่ายลึกเทรนได้เพราะ residual connection (ทางด่วนของ gradient) และ layer norm (รีเซ็ตสเกลทุกชั้น) ส่วน GPU, bf16, int4 และ gradient checkpointing คือการต่อรองระหว่างความเร็ว ความละเอียด และ VRAM ที่ค่า config ของเราตั้งอยู่
